# Documentation

本ディレクトリでは，設計仕様，実験記録，背景資料，横断的な報告を分離して管理する．

```text
docs/
├── design/
│   ├── mathematics/
│   ├── architecture/
│   ├── implementation/
│   └── decisions/
├── experiments/
│   └── templates/
├── references/
└── reports/
```

## `design/`

現在の実装が準拠すべき仕様を記載する．数学的定式化，システム構成，具体的な実装方針，重要な設計判断を含む．仕様を変更した場合は，該当文書を更新する．

## `experiments/`

実験ごとに新しいディレクトリを追加し，目的，仮説，設定，結果，考察，次の課題を記録する．記録の構成・命名・判断基準の詳細は`experiments/README.md`に従う．

過去の実験記録は原則として上書きしない．具体的には次の通りとする．

- **書き換えてよいもの**：表記の統一（記号・命名・用語），表の書式，誤記，ファイルパスの修正．
- **書き換えないもの**：数値，結果の解釈，結論．これらを改める場合は，元の記述を残したまま，新しい節で修正内容と理由を追記する．

## `references/`

設計仕様そのものではなく，設計の背景となった外部資料（ドラフトノート，申請書など）を保管する．未確定の検討事項や実装スコープ外の内容を含みうるため，仕様としては扱わない．内容が`design/`と食い違う場合は`design/`側を正とする．

## `reports/`

複数の実験（`experiments/`配下の個別記録）を横断してまとめた，対外報告用の要約文書を保管する．個々の実験の生データ・詳細は`experiments/`側の記録を正とし，本ディレクトリの文書はそれらから引用する形でまとめる．ファイル名は日付＋内容とする．

書式は`references/2026_JSAI_arakawa.pdf`に倣う：である調の学術文体とし，一般的な導入や付録は省く．結果表は1行に1条件・1手法を置き，指標ごとに列を分ける．LinearとBézierのコストを並べる表では，Bézier側のセルを「値 ($\Delta J$)」の形にする．それ以外では1つのセルに複数の数値を詰め込まない．
