## 記号と指標

- $J$：1問題の追跡コスト．全解パスについての$N_{\mathrm{acc}}+\rho N_{\mathrm{rej}}$の平均（$N_{\mathrm{acc}}$は受理ステップ数，$N_{\mathrm{rej}}$は棄却ステップ数，$\rho=1$）．追跡に失敗したパスには失敗ペナルティ$10^5$を課す．
- $J_{\mathrm{lin}}$：線形パス（制御点を開始系と目的系の線形補間に置いたパス．行動ゼロに等しい）の$J$．$J_{\mathrm{oracle}}$：oracleの最良行動での$J$．$\overline{J}$：対象の問題集合での$J$の平均（表の「平均$J$」）．
- $\Delta J$：線形パスに対する平均追跡コストの変化率．$\Delta J=(\overline{J}_{\text{手法}}-\overline{J}_{\mathrm{lin}})/\overline{J}_{\mathrm{lin}}\times100$（%）．負の値が改善．特に断らない限り，評価100問題（評価seed 39000〜39099）での値．差は「ポイント」で表す．
- Positive rate：問題集合のうち，その手法の$J$が線形パスの$J$より小さかった問題の割合．
- 成功率：追跡に失敗しなかった問題の割合．
- 到達率：$(\overline{J}_{\mathrm{lin}}-\overline{J}_{\text{手法}})/(\overline{J}_{\mathrm{lin}}-\overline{J}_{\mathrm{oracle}})$．oracleの改善量のうち手法が得た割合．分母のoracleは必ず明記する．評価100問題では，基準を「EXP-0017の比較用oracle（フル潜在，$d_b=2$，予算$B=3000$，100問題，$\Delta J=-31.65\%$，平均$J=30.1025$）」を主とし，同oracleの各問題の先頭1000評価の最小値（予算$B=1000$，$\Delta J=-29.78\%$，平均$J=30.9250$）も併記する．
- oracle：学習を使わず，評価問題ごとに行動を直接探索した結果（ゼロ行動，一様乱数，(1+1)進化戦略）．有限回の探索なので改善余地の下界．
- 予算$B$：oracleが1問題に使う試し追跡の回数（最初の100回はゼロ行動と一様乱数）．教師データ（ラベル）は$B=500$である．
- $n$，$d_i$，$N_{\mathrm{path}}=\prod_i d_i$：変数の数，方程式$i$の次数，追跡する解パスの数．系の名前（n4-d2222）は「変数の数4，次数(2,2,2,2)」を表す．
- $a_{i,j}$，$b$：目的系の係数と，その生成範囲（実部・虚部を$[-b,b]$の一様分布から生成．本記録では$b=1.0$）．
- $D_{\mathrm{free}}$：自由な（先頭以外の）複素係数の個数（n4-d2222で20）．観測は$2D_{\mathrm{free}}=40$次元の実ベクトル．
- $d_b$：ベジェ曲線の次数（本記録では$d_b=2$，中間制御点1つ）．$m$：潜在次元（中間制御点1つあたりの行動の次元）．「フル潜在」は$m=2D_{\mathrm{free}}=40$で，行動の次元は$(d_b-1)m=40$．
- BC：行動模倣（behavior cloning）．oracleの最良行動を正解とする教師あり学習．本記録のBCはすべて対称性拡張あり（学習中に問題族の対称群の元（768個）を作用させて観測と行動を変換する）．
- 「10k」「30k」：BCの教師データの件数（10000件，30000件）．「e1667」「e5000」：BCのエポック数（1667，5000）．
- 検証損失：教師データのうち検証用10%での，BCの出力と教師行動の二乗誤差の平均（10kでは1000件，30kでは3000件）．
- 最良epoch：検証損失が最小のエポック．評価にはその重みを使う．
- 試験問題：評価seed 41000〜41499の500問題．EXP-0020で追加した再評価に使う（5.4節）．

## 2．目的

スクリプトの記述：n4-d2222（$d_b=2$）で，教師データを増やすとBCは改善するか．新たに20000件のラベル（問題seed 8010000＋500k，EXP-0017の8000000〜8009999と重ならない）を作り，EXP-0017の10000件と合わせた30000件でBC（対称性拡張あり，3層256）をseed 0〜2で学習する．2つの条件を比べる．

- (a) `e5000`：5000エポック（EXP-0017と同じエポック数．更新回数は3倍）
- (b) `e1667`：1667エポック（EXP-0017と同じ更新回数）

EXP-0014（7.2節）には，n4-d2222では入力次元あたりのデータが少ないことが原因かもしれないという仮説が記されており，ラベル数を変えた対照実験は行っていないとされていた（未確認）．本実験は，ラベル数を変えたBCを行う．

## 3．多項式系

**n4-d2222**（$n=4$，次数$(2,2,2,2)$，$N_{\mathrm{path}}=16$，観測次元40）

- 開始系 $G=\{g_1,g_2,g_3,g_4\}$：
  $$g_1=x_1^2-1,\qquad g_2=x_2^2-1,\qquad g_3=x_3^2-1,\qquad g_4=x_4^2-1$$
- 目的系 $F=\{f_1,f_2,f_3,f_4\}$：
  $$f_i=x_i^2+a_{i,1}x_1+a_{i,2}x_2+a_{i,3}x_3+a_{i,4}x_4+a_{i,5}\quad(i=1,\dots,4)$$

係数$a_{i,j}$は問題ごとに異なり，実部と虚部をそれぞれ$[-1,1]$の一様分布から独立に生成する（複素一様分布，$b=1.0$）．先頭係数（$x_i^2$の係数）は1に固定する．ベジェ次数は$d_b=2$（行動40次元）．

## 4．方法

### 4.1．共通設定

追跡設定（設定ファイル）：最大ステップ数50000，最大ステップ幅0.05，最小ステップ幅$10^{-12}$，拡張精度なし，棄却ステップの重み$\rho=1$，失敗ペナルティ$10^5$．`path.action_limit`は1.0．

### 4.2．追加ラベル

`oracle.py --latent-dim full --budget 500 --n-random 100 --search-seed 0 --num-instances 500 --evaluation-seed $((8010000+500k))`（$k=0,\dots,39$の40 shard，計20000問題，評価seed 8010000〜8029999）．

### 4.3．BC

`behavior_cloning.py --latent-dim full --augment-symmetry --hidden-sizes 256,256,256 --epochs <5000または1667> --batch-size 256 --learning-rate 1e-3 --val-fraction 0.1 --seed s --oracle-run-dir <EXP-0017の連結oracle>`（$s=0,1,2$）．ラベルはEXP-0017の20 shard（10000件）と本実験の40 shard（20000件）の計30000件（訓練27000件，検証3000件）．`--oracle-run-dir`にはEXP-0017の評価100問題の連結oracle（予算$B=3000$）を指定した．比較対象のEXP-0017のBC拡張ありは，10000件（訓練9000件，検証1000件），5000エポック，seed 0〜2である．

### 4.4．判断基準（スクリプトの冒頭コメントによる事前登録）

- 条件(b)`e1667`の到達率（評価100問題，3seed平均）がEXP-0017のBC（10000件，拡張あり，3seed平均）を**+0.05以上**上回る → 教師データの量が効く．
- コメントでは分母を「自身のoracle，$B=1000$」としている．本記録では，分母をEXP-0017の連結oracleの予算$B=3000$とした値を主とし，$B=1000$の値を併記する（どちらでも判定は同じ，5.2節）．

## 7．観察

- 追加した教師データ2万件の平均$\Delta J$は$-29.75\%$で，既存の1万件（$-29.74\%$）と同じ品質だった．

- 試験500問題では，EXP-0017との差は次のとおり（いずれも30k−10k）．
  - `e1667`：到達率+0.009（95%区間$[-0.004,+0.022]$），$\Delta J$は$-0.27$ポイント（$[-0.66,+0.12]$）

## 8．考察

- 教師データを3倍にしても，教師あり学習の到達率の改善は+0.02以内だった．データの量は，MLPの教師あり学習の律速ではない．
- 学習損失と検証損失がほぼ一致するので，過学習は起きていない．拡張つきの学習では実質的なデータが多いため，これは予想どおりである．
- それでも損失が約0.117から下がらない原因として，次の2つが考えられる．
  1. MLPの表現力や帰納バイアスの不足 → EXP-0020（attention方策）で検証する．
  2. 教師データの雑音．oracleの解は問題ごとに一意ではなく，予算500の探索で選ばれる．このため，近い問題でも離れた行動がラベルになり得る．二乗誤差の回帰は，その平均を学ぶことになる．
- 2.が原因なら，モデルを変えても改善は限られる．その場合は，ラベルの一貫性を高める工夫が必要になる．
- `e5000`の小さな改善（試験問題で区間が0を含まない）は，更新回数が3倍になったことによる可能性がある．ただし，効果は小さく，実用上の差ではない．

## 9．結論

- 事前登録した基準（+0.05以上）を満たさない．n4-d2222のMLPの教師あり学習は，データ量では律速されていない．
