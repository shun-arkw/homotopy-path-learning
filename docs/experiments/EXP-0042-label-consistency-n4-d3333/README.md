# EXP-0042：教師データの一貫化（既存の3組のラベルの使い方，n4-d3333）

> 本記録の1〜6節は，実験の実行前（2026-10-15 03:00 JST頃）に書いた事前登録である．結果を見た後に1〜6節を変更する場合は，変更した箇所と理由を明記する．設計の経緯は`docs/design/drafts/2026-10-15-label-consistency-finetune/`にある．

## 2．目的

- 診断（2026-10-15）で，同じ目的系に対する3回の探索のラベルは互いに0.95離れ（ノルム2.0），移動方向の相互コサインは0.15で，ラベルの分散の約6割（推定．ラベル間の対距離から計算した1座標あたりの分散0.011を，検証MSE 0.018と比べた値）が目的系の関数として学習できないことが分かった．教師あり学習の出力はラベルより3ラベルの重心に近い（0.51対0.74）．
- 追加の追跡なしで，既存の3組のラベルの使い方を変えて，この分散の影響を減らせるかを調べる．
- 2つの腕は，ラベルの地形に対する仮定が異なる．A1（重心）は「同じ目的系の3ラベルが1つの谷の中にある」ことを仮定する（重心が峰に乗ると損をする）．A2（最近傍）は「どれか1つに寄ればよい」ので，谷が分かれていても成り立つ．D3（n4-d2222，ゼロからの探索のラベル）では約1/4の対で中点が乱数の対照より悪く，谷が分かれている目的系が混じる．ただし第1周のラベル（方策出力の近傍）では，2ラベルの中点の悪化が+2.7ポイント（同じノルムの乱数では+10.4）で，1つの谷に収まる割合が高いと見込む（未測定）．

## 4．方法

記号：目的系$i$の方策$k$由来のラベルを$\boldsymbol{a}^*_{i,k}$（$k=0,1,2$），ネットワーク出力を$\boldsymbol{\mu}(\boldsymbol{x}_i)$とする．

### 4.1．目的系の集合（3段階）

| 集合 | seed | 使い道 |
|---|---|---|
| 検証（従来） | 9600000〜9600199（200） | 微調整で採用する反復の選択 |
| **開発（新設）** | **9310000〜9310499（500）** | 腕の比較と選択（第1段） |
| 試験 | 9300000〜9300499（500） | 選んだ腕と基準線の最終比較（第2段，**1回だけ**） |

開発集合はn4-d3333では未使用のseed範囲である（EXP-0018／0023／0024／0025／0035／0038の記録と`outputs/`のrun名を確認．学習データ9000000〜9009999，検証9600000〜，微調整の訓練9700000〜9763999および9800000〜，試験9300000〜9300499のいずれとも重ならない）．

### 4.2．腕（教師あり学習の段階）

すべての腕で，ネットワークはattention（$d_{\mathrm{model}}=128$，4ヘッド，4層，FFN 256），対称性による拡張あり，300エポック，バッチ256，学習率$10^{-3}$，検証10%，ゼロから学習，seed 0〜2（3seed）．すなわち第1周（EXP-0038）と教師データ・損失以外は同じ．

| 腕 | 教師データ | 損失 | 必要なコード変更 |
|---|---|---|---|
| 基準線（既存，EXP-0038） | best-of-3 | 二乗誤差 | — |
| A1 重心 | 3ラベルの重心（`centroid_labels.py`で作成） | 二乗誤差 | データスクリプトのみ |
| A2 最近傍 | k0, k1, k2 の3組（`--label-group`，$K=3$） | $\min_k\|\boldsymbol{\mu}-\boldsymbol{a}^*_{i,k}\|^2$（`--label-reduction min`） | A2 |

- A2の検証損失は同じ`min`損失で計算する（基準線の検証MSEと直接は比べない）．
- 温間開始は，初期値とラベル集合を同時に変えて効果の帰属ができないため，腕から外した．

### 4.3．微調整

各腕の3つのcheckpointに，第1周と同じ微調整（2000反復，$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$，検証seed 9600000，訓練seed 9700000，検証200目的系，50反復ごと，8ワーカー）を行う．EXP-0043の結果が先に出て標準設定が変わる場合も，本実験では第1周と同じ設定を使う（EXP-0042の効果を単独で測るため）．

### 4.4．実行前の確認（基準線のずれ）

コード変更（A2，D4，B3）の後，EXP-0042の腕を走らせる前に`docs/design/implementation/label_consistency_finetune.md` 6節の確認を行う．

- (a) EXP-0038のBC seed 0のcheckpointから，新しいコードで新しい引数を使わずに微調整を200反復行い，`finetune_metrics.csv`（経過時間を除く）と`val_metrics.csv`（反復0，50，100，150，200の5行）が元のrunの先頭200反復と完全に一致すること．一致しなければ止める．
- (b) 第1周BC seed 0を新しいコードで学習し直し（GPU），最終の検証損失が元の0.0192に対して5%以内であること（参考．小さい差では止めない）．
- (c) 第1周BC seed 0と同じ設定（best-of-3ラベル，attention，対称性による拡張）を**CPUで3エポック**，変更前のcommit（別の作業ツリー）と新しいコード（新しい引数なし）で学習し，`train_metrics.csv`と保存した重みが完全に一致すること．CPUのtorchでこれらの演算が決定的でない場合は，重みの最大絶対差を記録し，$10^{-6}$未満であることを要求する（その場合はそう記録する）．一致しなければ止める．

### 4.5．評価と比較

- 基準線（EXP-0038 FT seed 0〜2）を開発集合で評価する（評価のみ．追加の学習はない）．
- 比較は`compare_runs.py`（3seedの方策のコストを目的系ごとに平均し，対応のあるブートストラップ，95%，2000回）．

## 5．判断基準（実行前に固定）

**第1段（開発集合，500目的系）：** 微調整後の$\Delta J$の差（腕−基準線）が，A1，A2のそれぞれで$-1.0$ポイント以下，かつ95%区間が0を含まない → その腕は候補．2腕を独立に判定し，補正は行わない（明記する）．候補が2つなら，開発集合での改善が大きい腕を選ぶ．差が0.5ポイント以内なら，実装が簡単なA1を選ぶ．

**第2段（試験集合，500目的系，1回だけ）：** 選んだ腕だけを基準線と比べ，同じ規則（差$\le-1.0$ポイント，区間が0を含まない）を満たせば標準手順に採用する．第1段で候補がなければ試験集合は使わない．

- 試験集合の使用回数について：本実験とEXP-0043は別の実験で，それぞれ第2段で1回ずつ試験集合を使う．合計2回の使用になることを明記する（EXP-0038以前の使用に加えて）．第2段の結果だけが試験集合での値として報告される．
- **組み合わせについて：** 本実験で採用した腕とEXP-0043で採用した腕を同時に使う構成（A＋B）は，本実験とEXP-0043だけでは採用しない．組み合わせの確認は，別に予約した第2の試験集合（seed 9320000〜9320499，500目的系，未使用を確認済み）で，EXP-0038の第1周の基準線に対して同じ規則（差$\le-1.0$ポイント，区間が0を含まない）により**1回だけ**行う（`docs/design/drafts/2026-10-15-label-consistency-finetune/`docs/design/drafts/2026-10-15-label-consistency-finetune/summary.md`` 3.1節の事前宣言の追試験）．
- **副（参考）：** 教師あり学習の段階での同じ差（開発集合）．学習データ500目的系での教師データとの差（現状5.5〜5.9ポイント）が2ポイント以上縮まるか．
- **否定的な結果の読み方：** 第1段で2腕とも候補にならなければ，「既存のラベルの使い方では，1ポイント以上の改善は得られない」と結論する．考えられる理由は，分散の影響が本方法では取り除けないこと，効果が1ポイント未満であること，微調整の検証選択の揺らぎ（±0.5ポイント）である．次はEXP-C（近接型の探索による再ラベル）か代理モデルへ進む．A1だけ候補にならずA2が候補なら，谷が分かれている目的系の影響が示唆される（D3の約1/4と整合）．

## 6．中断の条件

- 4.4(a)または(c)で一致しない場合（(c)は重みの最大絶対差が$10^{-6}$以上の場合）．
- A1の重心ラベルで，観測・線形コストの不一致が1件でもあれば止める（データの取り違え）．
- 損失の発散，追跡失敗が1%を超えた場合．
- 判断基準を結果を見てから変えない．
