# EXP-0036：n5-d33333の微調整の延長（2000反復→4000反復）

## 1．基本情報

- 実験ID：EXP-0036
- 状態：Planned（事前登録）
- 設定ファイル：`experiments/multivariate_pham/configs/exp-0028-n5-d33333-db2.yaml`
- 対象：EXP-0034のattention＋微調整（2000反復）の方策（seed 0〜2）
- 実行環境：外部サーバ（GPU 4台のサーバ）の参照Docker`homotopy-continuation`．追跡はCPU．

## 2．目的

- EXP-0034では，微調整の検証$\Delta J$が2000反復の時点でもまだ改善していた（反復1000で約$-24\%$，反復2000で約$-25\%$）．
- 微調整をさらに2000反復続けると，どこまで改善するかを調べる．EXP-0024（n3，n4）と同じ手順である．

## 3．多項式系

EXP-0034と同じ（n5-d33333，$d_b=2$，行動60次元，243パス）．

## 4．方法（事前登録）

- EXP-0034の微調整（2000反復）の方策（seed 0〜2）を初期値とし，同じ設定でさらに2000反復の微調整を行う（合計4000反復）．
  - 設定：$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$，検証200問題，50反復ごとに検証．
  - 検証seedは元の微調整と同じ11600000とする．検証$\Delta J$が最良の反復の重みを採用する点も同じである．
  - 訓練seedは，元の微調整と別の11800000とする．同じ訓練問題を繰り返さないためである．
  - 追跡は1 runあたり8ワーカーで並列に行う（`--workers 8`．結果はワーカー数によらない）．EXP-0035と同時に実行するため，EXP-0034の10ワーカーより減らす．
- 延長後の方策を，EXP-0034の試験問題（評価seed 9530000〜9530499，500問題）で評価する．
- 2000反復の方策（EXP-0034）と，`compare_runs.py`で比べる（3seedの方策のコストを問題ごとに平均し，対応のあるブートストラップ，95%，2000回）．到達率の分母は，EXP-0034の試験oracle（予算1000，探索seed 0）とし，参考の値とする．

## 5．判断基準（実行前に固定）

- 延長後−2000反復の，試験500問題での$\Delta J$の差が$-1.0$ポイント以下で，かつ95%区間が0を含まない → 2000反復では微調整が不足していた．
- 延長した2000反復のうち，検証$\Delta J$の最良が最後の500反復（反復3500以降）にある seed があれば，4000反復でも頭打ちでない可能性として報告する．
