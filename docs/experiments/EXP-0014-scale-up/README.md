## 2．目的

EXP-0010〜0013で整えた標準パイプライン（フル潜在oracleのラベル → 対称性拡張つきBC → 追跡コストの直接最小化による微調整）が，パス数の多い系（n3-d333）と，変数数の多い系（n4-d2222）に拡大しても機能するかを調べる．対称性の群は系が大きいほど大きくなる（拡張の効果も大きくなると予想される）．

## 3．方法・設定

### 3.1．予備oracle

各系で，評価seed（38000〜38099，39000〜39099）の100問題に対し，フル潜在空間で予算$B=3000$のoracleを実行した（`--budget 3000`，4 shard×25問題）．この結果を連結して比較用のoracleとする．到達率の基準は，予算3000のoracleと，各問題のoracleコストの先頭1000評価の最小値（以下$B=1000$）の2通りで求める．

### 3.2．ラベル

`oracle.py --latent-dim full --budget 500 --n-random 100 --search-seed 0 --num-instances 500`を20 shard（計10000問題）．評価seedの基点はn3-d333が7000000，n4-d2222が8000000．

### 3.3．BC

`behavior_cloning.py --latent-dim full --hidden-sizes 256,256,256 --epochs 5000 --batch-size 256 --learning-rate 1e-3 --val-fraction 0.1`．対称性拡張あり（`--augment-symmetry`，seed 0,1,2）と，拡張なし（seed 0）．

### 3.4．微調整

`finetune.py --latent-dim full`．初期方策は拡張ありBCの各seed．`--iterations 2000 --batch-problems 32 --pairs 4 --sigma 0.05 --learning-rate 1e-4 --bc-weight 0 --seed s --val-instances 200 --val-interval 50`．検証seedはn3-d333が7600000，n4-d2222が8600000，訓練seedはそれぞれ7700000，8700000．EXP-0013で選んだ$\sigma=0.05$をそのまま用いた．

## 4．判断基準（実行前に固定，$B=1000$基準）

- 両系で，微調整後の到達率が0.6以上 → パイプラインは規模拡大に耐える
- 拡張ありBCの到達率が拡張なしより+0.10以上 → 群が大きい系でも対称性の効果が大きい
- 微調整後の到達率が0.4未満 → 規模拡大でボトルネックが生じた（BCと微調整のどちらが伸びていないかで原因を切り分ける）
