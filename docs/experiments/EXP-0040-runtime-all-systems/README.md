# EXP-0040：追跡の計算時間（全8系の種類）

## 1．基本情報

- 実験ID：EXP-0040
- 状態：Planned（事前登録）
- 実行環境：メインの作業環境の参照Docker`homotopy-continuation`．1プロセス・1スレッドで，他の計算がない状態で計測する．ネットワークはCPUで計算する．
- コードの変更：なし（`experiments/multivariate_pham/timing.py`はEXP-0020で追加済み）．パスごとのステップ数の集計は，実験フォルダに置く小さなスクリプトで行う．

## 2．目的

- 2026-10-16の報告で，ステップ数の削減が計算時間の削減につながるかを示す．これまで計算時間は，EXP-0020のn4-d2222でしか測っていない（追跡が約2.3 msと軽く，ネットワークの計算約1.4 msの分だけ，全体では線形パスより48%遅かった）．
- 実際のソルバーでは解のパスを並列に追跡するので，目的系1つ分の合計時間だけでなく，パス1本あたりの追跡時間と，最も長いパスのステップ数も示す．

## 4．方法（事前登録）

- **計算時間：** `timing.py`で，目的系ごとにウォームアップ3回の後に5回測り，中央値をとる（EXP-0020と同じ）．
  - 線形パス：制御点の構成と追跡．
  - ネットワーク：観測の構成，ネットワークの計算（バッチ1，勾配なし），制御点の構成，追跡．
  - スレッドの環境変数（`OPENBLAS_NUM_THREADS`，`JULIA_NUM_THREADS`，`OMP_NUM_THREADS`）を1にし，系の種類を1つずつ順に測る．
- **パスごとのステップ数：** 同じ100個の目的系で，線形パスとネットワークのパスを1回ずつ追跡し，パスごとの受理・棄却のステップ数を記録する．
- **報告する値（目的系100個の平均）：**
  - 全体の時間（ms），ネットワークの計算の時間（ms），追跡の時間（＝全体−ネットワークの計算）．
  - パス1本あたりの追跡時間（＝追跡の時間÷パスの数）．
  - 線形パスとの時間比（全体どうし，追跡どうし）．
  - ステップ数：パス1本あたりの平均と，最も長いパスのステップ数（目的系ごとの最大の平均）．
- **並列化の参考値：** 全パスを十分な数のコアで並列に追跡するとき，終わるまでの時間はおおよそ「ネットワークの計算＋最も長いパスの追跡」で決まる．最も長いパスの追跡時間は，パスごとの時間を測っていないので，「最も長いパスのステップ数×1ステップあたりの平均時間」で見積もる（見積もりであることを明記する）．

## 5．判断基準（実行前に固定）

- 記述的な計測であり，合否の基準は設けない．
- 系の種類ごとに，4節の値を表にして報告する．

## 6．中断の条件

- 計測中に他の計算が動いていることが分かった場合は，その系の種類を測り直す．
- 計測した平均のステップ数（`timing.py`の`mean_cost`）が，既存の試験の評価の同じ目的系の値と一致しない場合は止めて報告する（ネットワークや設定の取り違えの確認）．
