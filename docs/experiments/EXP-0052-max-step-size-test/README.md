## 2．目的

- これまでのすべての追跡は，最大ステップ幅`max_step_size`を0.05にしている（$t\in[0,1]$の区間で，1ステップは0.05まで）．このため，どのパスも最低20ステップかかる．
- 学習したベジェ曲線のパスでは，多くのパスがこの下限の近くにある（例：n5-d33333でパスごとのステップ数の最小は20）．上限がなければ，ベジェ曲線のパスはさらに少ないステップで追跡できる可能性がある．一方，線形パスも上限が緩むと減る．
- 本実験では，学習と微調整をし直さずに，テストデータの追跡だけで上限を緩め，線形パスとベジェ曲線のパスのステップ数と削減率がどう変わるかを調べる．

## 4．方法（事前登録）

### 4.1．追跡の設定

- `max_step_size`を0.05（今の設定），0.1，0.2，0.5，1.0の5通りにする．1.0は$t$の区間全体の幅なので，事実上「上限なし」である．
- ほかの追跡の設定（最初のステップ幅の上限`max_initial_step_size: 0.05`，最小のステップ幅，最大のステップ数など）は変えない．
- ネットワークの出力（中間制御点）は，追跡の設定によらず同じである（入力は目的系の係数だけ）．スクリプトは，差し替えた設定と元の設定で入力が一致することを目的系ごとに確かめる．

### 4.2．評価

- 系の種類・$d_b$・上限の値ごとに，テストデータの500個で，線形パスと3つのネットワークのパスを追跡する．
- 目的系ごとに次を記録する：受理・棄却のステップ数，追跡に失敗したパスの数，**取りこぼした解の数**．
  - 取りこぼした解：元の設定（0.05）の線形パスの終点を参照の解とし，どの終点からも相対誤差$10^{-6}$以内にない参照の解の数．上限を緩めたときに，パスが別の解へ飛び移ると，解を取りこぼす．

### 4.3．報告する値

- 系の種類・$d_b$・上限の値ごとに：
  - 線形パスとベジェ曲線のパスの平均ステップ数$\bar J$（ベジェ曲線は，3つのネットワークのステップ数を目的系ごとに平均した値）．
  - 削減率と95%区間（目的系ごとに対応をとったブートストラップ，2000回）．
  - 削減率の変化（その上限での削減率 − 0.05での削減率）と95%区間（同じブートストラップ）．
  - 線形パスとベジェ曲線のパスの$\bar J$の，0.05からの変化率．
  - 棄却のステップの割合，追跡に失敗したパスの数，取りこぼした解の数．

## 5．判断基準（実行前に固定）

- 取りこぼした解が1つでもある設定では，そのことを削減率と並べて示す．削減率だけで「良い設定」とは言わない．
- 本実験の結果を見て，追跡の設定を変えた学習や微調整を行うかは，別の実験として提案する．

### 7.3．観察

- 上限を緩めると，線形パスもベジェ曲線のパスもステップ数が減り，ベジェ曲線のパスの方が大きく減った．そのため削減率はすべての系の種類で上がった．
- ただし，上がり方は系の種類で大きく違う．n2-d22では+7.6ポイントだが，n5では+0.1ポイント程度である．
  - n2-d22では，上限0.05のとき，学習したパスの平均ステップ数が21以下の目的系が53%あった（下限は20）．上限が多くのパスで効いていた．n4-d3333とn5-d33333では，そのような目的系はなかった．変数や次数の大きい系では，追跡のステップ幅は上限より小さいところで決まっており，上限はほとんど効いていない．
- 上限を0.1から1.0まで変えても結果はほぼ変わらなかった．上限0.05を外すと，ステップ幅はおおむね0.1以下に収まっていたことになる（最初のステップ幅の上限0.05は変えていない）．
- 解の取りこぼし，追跡の失敗，棄却されたステップは，どの設定でも0だった．この500個の目的系では，上限を外しても追跡の正しさは保たれた．
- 報告の表の削減率（上限0.05）は，小さい系の種類（特にn2）では，上限がベジェ曲線のパスの利点を押さえた値になっている．n4以上では，上限の影響は0.7ポイント以下である．
- ネットワークは上限0.05で学習したものである．上限を緩めた条件で微調整し直せば，さらに変わる可能性があるが，本実験では調べていない．

### 7.4．訂正（2026-10-17，実験の後に判明）

- `eval_cap.py`は，参照の解を求める環境（元の設定）と評価する環境（緩めた設定）を，同じプロセスの中で作っていた．同じプロセスの中で作った環境は，Julia側の追跡の状態（ホモトピーと追跡の設定）を1つ共有しており，最後に作った環境の追跡の設定が，すべての環境の追跡に使われる．このことは，EXP-0055の準備中（2026-10-17）に，同じスクリプトの構成で設定ごとの結果が一致してしまうことから気づき，確かめた．
- そのため，参照の解は，4.2節に書いた「元の設定（0.05）の線形パスの終点」ではなく，**評価と同じ上限で追跡した線形パスの終点**だった．
  - 線形パスの「取りこぼした解」は，自分自身と比べているので常に0になり，意味を持たない．
  - 学習したパスについてわかるのは，「同じ上限の線形パスの終点にすべて着いた」ことだけである．線形パスの終点に重複がないか（すべての解に着いたか）は確かめていない．
  - したがって，**7.1節と7.3節の「解の取りこぼしは0」は，事前登録した意味では確かめられていない**．
- 7.2節のステップ数と削減率，7.1節の上限0.05での再現の確認には影響しない（評価する環境は，最後に作られたので正しい設定で追跡していた）．
- 参考：EXP-0053では，上限を外した設定（ほかは既定）で，$d_b=3$の8つの系の種類の開発集合の各500個について，線形パスの終点が重複のない$N$個の解（解はちょうど$N$個なので，すべての解）であり，学習したパスもそれらすべてに着いたことを確かめた（EXP-0053の7.6節）．$d_b=2$のネットワークとテストデータについては確かめていない．
