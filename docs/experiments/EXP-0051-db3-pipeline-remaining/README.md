## 2．目的

- EXP-0047とEXP-0050で，$d_b=3$の標準の手順は，n4-d3333，n5-d22222，n5-d33333のすべてで$d_b=2$より良かった（テストデータで+1.4〜+2.5ポイント）．EXP-0050の判断に従い，報告の残りの系の種類にも$d_b=3$を広げる．
- 残りの5つの系の種類のうち，n2-d33とn3-d333には，$d_b=3$の標準の手順のネットワークがすでにある（EXP-0026，EXP-0021．教師データは予算500，ランダム100，全次元で，標準の手順と同じ）．EXP-0039では，テストデータで$d_b=2$との差が，n2-d33で+0.41［−0.22, +1.05］，n3-d333で+1.42［+1.02, +1.83］ポイントだった．
- そこで，本実験では次の2つを行う．
  - n2-d22，n3-d222，n4-d2222：$d_b=3$の標準の手順を新たに行う．
  - 5つすべて：新たに予約する開発集合で$d_b=2$と$d_b=3$を比べ，系の種類ごとに判断する．

### 4.3．手順（n2-d22，n3-d222，n4-d2222．標準の手順）

1. **教師データ：** `oracle.py --latent-dim full --budget 500 --n-random 100 --search-seed 0`，20分割×500個（評価seedは学習データの先頭$+500k$）．
   - n3-d222とn4-d2222には，同じ目的系・同じ設定の$d_b=3$の教師データ（EXP-0011，EXP-0014）が古いコミットで作られている．手順をそろえるため，今のコードで作り直す．
2. **教師あり学習：** attention（$d_{\mathrm{model}}=128$，4ヘッド，4層，FFN 256），対称性による拡張あり，300エポック，バッチ256，学習率$10^{-3}$，検証10%，seed 0〜2．
3. **微調整：** 2000反復，$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$，検証200個（50反復ごと），seed 0〜2．
4. **第1段（開発集合）：** 5つの系の種類で，$d_b=2$と$d_b=3$の微調整後（各3つ）と，本実験の$d_b=3$の教師あり学習後（各3つ）を開発集合で評価し，5節の第1段を記録する．
5. **第2段（テストデータ，本実験で1回だけ）：** n2-d22，n3-d222，n4-d2222の$d_b=3$の6つのネットワーク（系の種類ごと）をテストデータで評価する．$d_b=2$は既存のテストデータの評価を使う．n2-d33とn3-d333は，EXP-0039の既存のテストデータの比較の値を使う（本実験ではテストデータを使わない）．

  - n3-d222とn4-d2222では，作り直した教師データの探索結果（`oracle_cost`）を古い$d_b=3$の教師データ（EXP-0011，EXP-0014）と比べ，一致しない目的系の数を記録する．

### 4.5．比較と報告する値

- 比較は`compare_runs.py`（3つのネットワークのステップ数を目的系ごとに平均し，目的系ごとに対応をとったブートストラップ，95%区間，2000回）．
- 主な比較：系の種類ごとに，$d_b=3$の微調整後 − $d_b=2$の微調整後．
- 補助の値：教師データの削減率と$d_b=2$の教師データとの差，教師あり学習後の削減率，微調整の検証での削減率の推移と最良の反復，各段階の所要時間．
- 注記：n4-d2222の$d_b=2$（EXP-0020）の教師あり学習は，今の標準の手順（300エポック）と同じではない．差の解釈ではこの点に触れる．

## 5．判断基準（実行前に固定）

差は「$d_b=3$の削減率 − $d_b=2$の削減率」（ポイント）で，正なら$d_b=3$の方が良い．判定はEXP-0047，EXP-0050と同じ．

| 判定 | 条件 |
|---|---|
| 良い | 差が+1.0ポイント以上で，95%区間が0を含まない |
| 悪い | 差が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

**第1段（開発集合）：** 系の種類ごとに独立に判定する（多重比較の補正はしない）．

| 判定 | 判断（ユーザーに提案すること） |
|---|---|
| 良い，差なし | その系の種類でも$d_b=3$を標準の手順にする（報告の表は$d_b=3$でそろえる） |
| 悪い | その系の種類では$d_b=2$を続ける |

- 判断は開発集合だけで行う．テストデータの結果を見て判断を変えることはしない．

**第2段（テストデータ）：** 第1段の結果によらず，$d_b=3$の値を求める．報告の表に載せる値は，微調整後の値とする．テストデータの比較も同じ規則で判定して記録する．

## 6．中断の条件

- 4.4節の環境の確認で，線形パスのステップ数が1件でも一致しない場合．
- 教師データの探索で，追跡に失敗した目的系が1%を超えた場合．
- 教師データの線形パスのステップ数が，$d_b=2$の教師データと一致しない目的系が1%を超えた場合（少数の不一致は記録して続ける）．
- 損失の発散（NaN），コンテナの停止が起きた場合．
- 判断基準を，結果を見てから変えることはしない．

### 7.4．観察

- $d_b=3$にして悪くなった系の種類はなかった．一方，n2〜n4の次数2の系の種類（n2-d22，n3-d222，n4-d2222）では，差はテストデータで+0.2〜+0.7ポイントと小さかった．
- 差は，次数が3の系の種類の方が大きい傾向がある．
  - 次数2：n2-d22は+0.2，n3-d222は+0.5，n4-d2222は+0.7，n5-d22222は+1.4．
  - 次数3：n2-d33は+0.4，n3-d333は+1.4，n4-d3333は+2.5，n5-d33333は+2.0．
  - 次数2でも，変数が増えるほど差が大きくなっている．
- これまでと同じく，効果は微調整の後にだけ現れた．
  - 教師データは，$d_b=3$の方が$d_b=2$より5〜7ポイント悪い．
  - 微調整で7〜11ポイント伸びて，$d_b=2$の微調整後と同じかわずかに上になった．
- n2-d22は，EXP-0052で，最大ステップ幅の上限（0.05）で決まるステップ数の下限（20）に近い目的系が多かった（上限0.05で，学習したパスの平均ステップ数が21以下の目的系が53%）．このため，パスの形をより自由にしても，ステップ数を減らす余地が小さい可能性がある．これは確かめていない．
