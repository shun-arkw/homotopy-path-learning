# EXP-0059：目的系は一般のまま，行動をランダムな小さい部分空間に絞ったとき，係数パスの探索はどれだけ速く，どれだけ良くなるか

- 状態：Planned（事前登録）

  - **行動の部分空間**：ベジェ曲線の中間の制御点は，線形補間に摂動$U\boldsymbol{z}_k$を加えて作る（`docs/design/implementation/bezier_path.md` 3節）．$U$は自由な係数の実ベクトル（実部と虚部，$2m$次元）の中の，列が正規直交な$2m\times\ell$の行列で，`path.basis_seed`から乱数で作る．$\ell$を**潜在次元**と呼ぶ．行動の次元は$(d_b-1)\ell$．$\ell=2m$（全次元）では$U$は正方の直交行列で，自由な係数のすべての向きに曲げられる．
  - **探索（oracle）**：目的系ごとに，追跡のステップ数$J$（受理と棄却の合計の，パス1本あたりの平均）が最小になる行動を直接探す（`experiments/multivariate_pham/oracle.py`）．最初に行動0（線形パス）と一様乱数の行動を合わせて`n_random`回評価し，残りを1/5成功則の進化戦略で探す．**予算**$B$は$J$を評価する回数．

- コードの変更：なし．設定ファイルは`experiments/multivariate_pham/configs/exp-0059-*.yaml`（6つ），スクリプトは`outputs/EXP-0059/scripts/`に置く（`run.sh`，`envcheck.py`，`summary.py`）．

## 2．目的

- 係数の数$m=n(n+1)$（複素）は変数の数$n$の2乗で増え，全次元の行動（$d_b=3$で$4m$次元）の探索は，教師データを作るときの主な時間になる．
- 「目的系の係数を部分空間$\boldsymbol{c}=W\boldsymbol{u}$に限り，行動も$W$の像に限る」案（以下，部分空間の族）を検討している．しかし，その効果は「探索空間が小さいこと」と「目的系の族が狭いこと」が混ざる．
- EXP-0009では，目的系を制限せずに行動をランダムな実4次元部分空間に絞っても，探索の改善量はn3-d222で$-22\%$（全次元$-26\%$）で，予算300でほぼ飽和した．
- 本実験では，目的系は今の一般の分布のまま，行動だけを小さい部分空間に絞り，新しい追跡の設定とより大きい系で次を調べる．
  1. 絞っても，探索が見つける改善量はどれだけ残るか．
  2. 今の教師データと同じ質の行動を，どれだけ少ない予算で見つけられるか．
- 結果が良ければ，部分空間の族を実装しなくても，一般の目的系のまま探索の時間を減らせる．その場合，族の制限は必須ではない．

- 学習をしないので，開発集合とテストデータには分けない．本実験の結果で潜在次元を選んだ場合，その後の実験は別の目的系で評価する．

## 4．方法（事前登録）

### 4.1．比べる設定

- 潜在次元$\ell\in\{4, 8, 16, 2m\}$（行動の次元は$d_b=3$で$2\ell$：8，16，32，全次元はn4-d3333で80，n6-d222222で168）．
- 基底のseed（`path.basis_seed`）：0，1，2．全次元でも3つ（全次元の基底は回転だけが違うが，探索の乱数の行動と箱への切り詰めは回転で変わる）．
- 系の種類2つ×潜在次元4つ×基底のseed 3つ＝24個のrun．各runで目的系100個．
- 追跡：新しい追跡の設定．$d_b=3$．行動の範囲`action_limit`=1.0．
- 探索：`oracle.py --latent-dim <ℓ|full> --budget 1000 --n-random 20 --search-seed 0 --evaluation-seed <基点> --num-instances 100`．進化戦略の初期の幅は既定の0.3．
  - 探索は総予算に依存しない（乱数の行動の後，1/5成功則で幅を変えるだけ）．よって$B=1000$の実行の`oracle_cost_traces.npy`の先頭$b$個の最小値は，予算$b$（$b\ge20$）で止めた探索の結果と同じである．$B=100$，300，500の値はこれから読む．
  - `n_random`は，今の教師データ（100）より小さい20にする．$B=100$がすべて乱数にならないようにするためである．

### 4.2．環境の確認

- 実行の前に，n4-d3333の`exp-0059-n4-d3333-db3-bw08-basis0.yaml`で，EXP-0058の開発集合の先頭5つの目的系（9310000〜9310004）の線形パスの$J$を計算し，EXP-0058の新しい追跡の設定（`W0.8-A0.125`）の線形パスの$J$と完全に一致することを確かめる（`envcheck.py`）．一致しなければ止める．
- n6-d222222も同じく9561000〜9561004で比べる．EXP-0058の評価は$d_b=2$なので，線形パスの評価の浮動小数点の違いでずれる可能性がある．ずれた場合は止めて，原因を調べてから進むかを決める．

### 4.3．報告する値

系の種類，潜在次元，基底のseedごとに（基底のseedの平均と範囲も）：

- 線形パスの平均ステップ数$\bar J_\text{lin}$．
- 予算$b$での改善量$\Delta J(b)=(\overline{J^*(b)}/\bar J_\text{lin}-1)\times100$（%）．$J^*(b)$は目的系ごとの先頭$b$回の評価の最小値，上の線は目的系の平均．$b\in\{100, 300, 500, 1000\}$．
- 保持率$R(\ell)=\Delta J_\ell(1000)/\Delta J_{2m}(1000)$（どちらも基底のseedの平均）．
- 必要な予算$B^*(\ell)$：基底のseedで平均した$\overline{J^*(b)}$が，全次元の基底のseedで平均した$\overline{J^*(500)}$以下になる最小の$b$（1000以内に届かなければ「未到達」）．全次元の予算500は，今の教師データの予算である．
- 1目的系あたりの時間（`elapsed_seconds`の平均）．1回の評価の時間は行動の次元にほとんど依らないので，教師データの時間は予算に比例する．
- 最良の行動が箱の境界に達した目的系の割合（`best_action_max_abs`≥0.999），追跡に失敗したパスを含む最良の行動の数．
- 不確かさ：目的系についてのブートストラップ（2000回，`default_rng(0)`を1回作り，系の種類，潜在次元の順に使う）で，$R(\ell)$と$\Delta J_\ell(1000)-\Delta J_{2m}(1000)$の95%区間．

## 5．判断基準（実行前に固定）

系の種類ごと，$\ell\in\{4,8,16\}$ごとに：

- **改善の保持**：$R(\ell)\ge0.85$．
- **速さ**：$B^*(\ell)\le250$（今の教師データの予算500の半分以下で，同じ質の行動に届く）．

全体の読み方：

- 2つの系の種類の両方で，ある$\ell<2m$が両方を満たせば，「目的系は一般のまま，行動をランダムな小さい部分空間に絞るだけで，教師データの探索の予算を半分以下にでき，改善量の大部分が残る」と書く．次は，その$\ell$で教師データ→教師あり学習→微調整の手順を試す計画を立てる（今のattentionのネットワークは正方の基底を前提にしているので，コードの変更が必要になる）．
- 改善の保持だけを満たす場合は，「改善量は残るが，探索は速くならない」と書く．
- どの$\ell$も改善の保持を満たさなければ，「ランダムな部分空間では改善量が失われる」と書き，部分空間の族（目的系も部分空間に限る案）を検討する．
- 系の種類で結果が分かれた場合は，そのとおり書き，$n$による違いとして記述する．
- 基準の数値（0.85，250）は，事前に決めた目安であり，結果を見て変えない．
