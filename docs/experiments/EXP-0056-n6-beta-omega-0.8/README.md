## 2．目的

- EXP-0055では，新しい追跡の設定で微調整だけをやり直すと，各3次の系（2〜5変数）では，線形パスに対する削減率が，これまでの追跡の設定のネットワークと同じか少し上がった（開発集合で+0.5〜+1.9ポイント）．各2次の系では2.3〜5.0ポイント下がった．どちらでもステップ数は約4分の1になった．
  - ここで削減率は，同じ追跡の設定で追跡した線形パスに比べて，学習したパスのステップ数（受理と棄却の合計）が何%減ったかである．
- 微調整だけをやり直した場合の差は，変数の数が増えるほど良くなる傾向が見えた（各3次：+0.5，+0.6，+1.0，+1.9．各2次：−4.3，−5.0，−3.4，−2.3．2〜5変数の順）．ただし次数ごとに4点しかなく，ネットワークの元の実験も種類ごとに違うので，確かではない．
- 本実験では，6変数の2つの系の種類で同じ比較を行い，この傾向が6変数でも続くかを調べる．教師データは作らない．
  - 6変数・各3次では，教師データを作ると1万個で約8時間（新しい追跡の設定）〜2日（これまでの追跡の設定）かかり，対称性による拡張も約105万通りになり，そのままでは教師あり学習ができない．
  - そこで，EXP-0048の転用したネットワークを出発点にして，6変数で微調整だけを行う．出発点は，2つの追跡の設定で同じである．

**開発集合での判断（系の種類ごと）：**

| 結果 | 判断（ユーザーに提案すること） |

**変数の数の傾向についての読み方（記述的．合否ではない）：**

- 6変数・各3次の差が，5変数・各3次（EXP-0055の開発集合で+1.90）と同じかそれより大きく，6変数・各2次の差が，5変数・各2次（−2.29）より0に近いか正なら，「変数が増えるほど，新しい追跡の設定で微調整したときの削減率が保たれやすい」という見方と合う．

- いずれの場合も，次数ごとに5点（2〜6変数）しかなく，6変数のネットワークは$d_b=2$で転用から始めている（2〜5変数は$d_b=3$で標準の手順）ことを，結論の限界として書く．

- 判断は開発集合だけで行う．テストデータの結果を見て判断を変えることはしない．
- テストデータでも，同じ規則で判定して記録する．

### 7.1．開発集合での判断（2026-10-18 20:26 JST，テストデータの評価の前に記入）

**事前登録からの変更（実行環境）**：6変数・各3次の微調整も，外部サーバではなくメインの環境で行った．6節の2つ目の条件に当たったためである．外部サーバで，転用したネットワークを新しい追跡の設定で開発集合の5個の目的系に使ったところ，線形パスのステップ数はメインの環境と一致したが，学習したパスのステップ数が数歩ずれた．ネットワークへの入力は両方の環境で一致し，出力（行動）は最大$2.7\times10^{-7}$だけ違った（CPUの違いによるfloat32の丸めの差と考えられる）．新しい追跡の設定では，この程度の差でもステップ数が変わる．これまでの追跡の設定では，同じ確認でずれは見られていない．記録は`outputs/EXP-0056/envcheck/`．微調整と評価はすべて，メインの環境（CPUのみ）で，作業ツリーcommit 68e96e2（コードは3c6ad69と同じ）から行った．

### 7.5．考察

- **6変数・各3次**：新しい追跡の設定で微調整したネットワークは，ステップ数を約4分の1（学習したパスで50.4→11.2，テストデータ）にしたうえで，削減率をこれまでの追跡の設定より約2.4ポイント上げた．学習し直さずに追跡の設定だけを変えると差はほぼ0なので，上がった分は，新しい追跡の設定で微調整したことによる．
- **6変数・各2次**：新しい追跡の設定では，学習し直さないと約2.5ポイント下がり，微調整で約0.6〜0.8ポイント取り戻したが，これまでの追跡の設定には届かなかった．
- **変数の数の傾向**：6変数の値は，両方の次数で，5節の読み方の条件（各3次は5変数の+1.90以上，各2次は5変数の−2.29より0に近い）を満たした．EXP-0055で見えた傾向は，6変数でも続いたと言える．ただし次の限界がある．
  - 次数ごとに5点だけで，各3次のテストデータでは2〜4変数で単調でない．
  - ネットワークの作り方が違う．6変数は，$d_b=2$で5変数から転用したネットワークを，新しい追跡の設定で微調整した．2〜5変数は，$d_b=3$で，これまでの追跡の設定の教師データで教師あり学習したネットワークを，新しい追跡の設定で微調整した．比べる相手も，6変数は転用から微調整したネットワーク，2〜5変数は標準の手順（教師データ・教師あり学習・微調整）で作ったネットワークである．
- **線形パスの取りこぼし**：開発集合のn6-d333333の1つの目的系（9571104）で，新しい追跡の設定の線形パスが解を1つ取りこぼした．同じ目的系で，学習したパス（3つの名前×3つのネットワーク）は取りこぼさなかった．テストデータでは線形パスの取りこぼしはなかった．2〜5変数（EXP-0055）では，線形パスの取りこぼしはなかった．1件だけなので，学習したパスのほうが取りこぼしにくいとは言えない．
- **計算機による違い**：7.1節に書いたとおり，新しい追跡の設定では，CPUの違いによる行動の$10^{-7}$程度の差で学習したパスのステップ数が変わる．同じ結果を再現するには，同じ機械で実行する必要がある．

### 7.6．結論

- 5節の規則による提案：
  - n6-d333333：新しい追跡の設定で微調整したネットワーク（新しい追跡の設定で使う）を今後の標準にする．
  - n6-d222222：これまでの追跡の設定を続ける．
- 新しい追跡の設定で微調整したときの削減率の差は，6変数でも，変数の数が増えるほど良くなる傾向に合った．

### 7.7．次の実験の候補

- 追跡の慎重さ（例えば`β_ω_p`を0.8，0.5，0.3と下げる）を変えて，線形パスと学習したパスの両方で，平均ステップ数と解の取りこぼしの割合を測り，取りこぼしの割合が同じ水準でのステップ数で比べる．線形パスが大きなステップで取りこぼし始めたとき，学習したパスが取りこぼさずに少ないステップで済むかを確かめる．EXP-0053の評価に，取りこぼしの数が残っていれば先に見直す．
