## 2．目的

- EXP-0055では，新しい追跡の設定で微調整だけをやり直すと，各3次の系（2〜5変数）では，線形パスに対する削減率が，これまでの追跡の設定のネットワークと同じか少し上がった（開発集合で+0.5〜+1.9ポイント）．各2次の系では2.3〜5.0ポイント下がった．どちらでもステップ数は約4分の1になった．
  - ここで削減率は，同じ追跡の設定で追跡した線形パスに比べて，学習したパスのステップ数（受理と棄却の合計）が何%減ったかである．
- 微調整だけをやり直した場合の差は，変数の数が増えるほど良くなる傾向が見えた（各3次：+0.5，+0.6，+1.0，+1.9．各2次：−4.3，−5.0，−3.4，−2.3．2〜5変数の順）．ただし次数ごとに4点しかなく，ネットワークの元の実験も種類ごとに違うので，確かではない．
- 本実験では，6変数の2つの系の種類で同じ比較を行い，この傾向が6変数でも続くかを調べる．教師データは作らない．
  - 6変数・各3次では，教師データを作ると1万個で約8時間（新しい追跡の設定）〜2日（これまでの追跡の設定）かかり，対称性による拡張も約105万通りになり，そのままでは教師あり学習ができない．
  - そこで，EXP-0048の転用したネットワークを出発点にして，6変数で微調整だけを行う．出発点は，2つの追跡の設定で同じである．

## 4．方法（事前登録）

### 4.1．出発点のネットワーク

EXP-0048の，5変数の系の種類からの転用（各3つ，seed 0〜2）：

| 系の種類 | run |
|---|---|
| n6-d222222 | `outputs/EXP-0048/exp-0048-n6-d222222-db2-from-n5-d22222-seed{0,1,2}-20261016T120524Z` |
| n6-d333333 | `outputs/EXP-0048/exp-0048-n6-d333333-db2-from-n5-d33333-seed{0,1,2}-20261016T120524Z` |

これらは5変数の系で標準の手順（教師データ，教師あり学習，微調整．すべてこれまでの追跡の設定）で作り，6変数では何も学習していない．

### 4.2．微調整

設定はEXP-0049と同じ（標準の手順の微調整）：2000反復，$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$，検証200個（50反復ごと），採用する重みは検証で最も良かった反復，seedは出発点と同じ0〜2．

| 系の種類 | これまでの追跡の設定で微調整 | 新しい追跡の設定で微調整 |
|---|---|---|
| n6-d222222 | 本実験で行う（設定`exp-0056-n6-d222222-db2.yaml`） | 本実験で行う（`exp-0056-n6-d222222-db2-bw08.yaml`，`--allow-init-tracker-difference`） |
| n6-d333333 | EXP-0049の3つを使う（`outputs/EXP-0049/exp-0049-n6-d333333-db2-ft-from-n5-seed{0,1,2}`） | 本実験で行う（`exp-0056-n6-d333333-db2-bw08.yaml`，`--allow-init-tracker-difference`） |

- ワーカーの数は結果に影響しない（EXP-0049と同じ前提）．
- 各runの開始と終了の時刻，ワーカーの数，機械を記録する．

### 4.3．評価

次の5つを，系の種類ごとに開発集合とテストデータ（各500個）で評価する．どれも3つのネットワーク（seed 0〜2）からなる．

| 名前 | ネットワーク | 評価の追跡の設定 |
|---|---|---|
| 転用・これまでの設定で評価 | 4.1節の転用（6変数では学習なし） | これまでの追跡の設定 |
| 転用・新しい設定で評価 | 同上 | 新しい追跡の設定 |
| これまでの設定で微調整・これまでの設定で評価 | 4.2節の「これまでの追跡の設定で微調整」 | これまでの追跡の設定 |
| これまでの設定で微調整・新しい設定で評価 | 同上（学習し直さずに追跡の設定だけを変える） | 新しい追跡の設定 |
| 新しい設定で微調整・新しい設定で評価 | 4.2節の「新しい追跡の設定で微調整」 | 新しい追跡の設定 |

- スクリプト：EXP-0053の`outputs/EXP-0053/scripts/eval_arm.py`をそのまま使う（ネットワークは各runの設定で読み込み，追跡の設定だけを差し替える．`A0`がこれまでの追跡の設定，`B0.8`が新しい追跡の設定）．作業ツリーはcommit 3c6ad69．
- 取りこぼしの判定はEXP-0055の4.1節と同じ：目的系ごとに，線形パスを慎重な設定（予測子は1次，HC.jlの`CONSERVATIVE_TRACKER_PARAMETERS`，`max_step_size`=0.05）で追跡した終点を参照の解とし，係数パスの終点のどれからも相対誤差$10^{-6}$以内にない参照の解の数を数える．参照の解がすべて追跡に成功し，重複がないことも確かめる．
- 環境の確認：「転用・これまでの設定で評価」と「これまでの設定で微調整・これまでの設定で評価」（n6-d333333）の，線形パスと学習したパスのステップ数が，EXP-0048とEXP-0049の評価（`evaluate.py`）と，開発集合の500個すべてで完全に一致すること．一致しなければテストデータの評価に進まずに止める．
- テストデータは，開発集合での判断（5節）を記録に書いた後に，1回だけ評価する．

### 4.4．報告する値

- 5つの名前ごとに，削減率（3つのネットワークのステップ数を目的系ごとに平均して計算する），線形パスと学習したパスの平均ステップ数，棄却されたステップの割合，追跡の失敗と取りこぼしの数．
- 比較の差と95%区間（目的系ごとに対応をとったブートストラップ，2000回，`default_rng(0)`）：
  - **主な比較**：「新しい設定で微調整・新しい設定で評価」の削減率 − 「これまでの設定で微調整・これまでの設定で評価」の削減率．EXP-0055の「微調整だけをやり直した場合 − これまでの追跡の設定のネットワーク」に当たる．
  - 補助の比較：「これまでの設定で微調整・新しい設定で評価」 − 「これまでの設定で微調整・これまでの設定で評価」（学習し直さずに追跡の設定だけを変えた場合）．「転用・新しい設定で評価」 − 「転用・これまでの設定で評価」（6変数で学習していないネットワーク）．
- 2〜5変数（EXP-0055の開発集合とテストデータ）と並べた表．
- 微調整の検証での削減率の推移（反復0，500，1000，1500，2000）と最良の反復．
- 微調整にかかった時間．n6-d333333は，EXP-0049（これまでの追跡の設定）と比べる（ワーカーの数が違うので，CPU時間＝時間×ワーカーの数でも比べる）．

## 5．判断基準（実行前に固定）

判定はEXP-0055と同じ．差は主な比較（ポイント）．

| 判定 | 条件 |
|---|---|
| 良い | 差が+1.0ポイント以上で，95%区間が0を含まない |
| 悪い | 差が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

**開発集合での判断（系の種類ごと）：**

| 結果 | 判断（ユーザーに提案すること） |
|---|---|
| 安全（開発集合で失敗も取りこぼしも0）で，判定が「良い」か「差なし」 | その系の種類では，新しい追跡の設定で微調整したネットワークを今後の標準にする |
| 安全でない，または判定が「悪い」 | その系の種類では，これまでの追跡の設定を続ける |

**変数の数の傾向についての読み方（記述的．合否ではない）：**

- 6変数・各3次の差が，5変数・各3次（EXP-0055の開発集合で+1.90）と同じかそれより大きく，6変数・各2次の差が，5変数・各2次（−2.29）より0に近いか正なら，「変数が増えるほど，新しい追跡の設定で微調整したときの削減率が保たれやすい」という見方と合う．
- そうでなければ，EXP-0055で見えた傾向は，6変数までは続かなかったと書く．
- いずれの場合も，次数ごとに5点（2〜6変数）しかなく，6変数のネットワークは$d_b=2$で転用から始めている（2〜5変数は$d_b=3$で標準の手順）ことを，結論の限界として書く．

- 判断は開発集合だけで行う．テストデータの結果を見て判断を変えることはしない．
- テストデータでも，同じ規則で判定して記録する．

## 6．中断の条件
