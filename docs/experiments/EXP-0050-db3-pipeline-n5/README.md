## 2．目的

- EXP-0047（n4-d3333）では，$d_b=3$の標準の手順（予算500）が$d_b=2$より，テストデータで2.5ポイント良かった（31.1%対28.6%）．予算を1000にしても変わらなかった．
- 同じ手順をn5の2種類で行い，$d_b=2$の標準の手順（報告3節：n5-d22222は20.9%，n5-d33333は24.8%）と比べる．
- 結果は，報告の表を$d_b=3$でもそろえる値と，「係数パスの表し方」が50%削減に届かない理由の1つかを考える材料にする．

## 4．方法（事前登録）

### 4.1．目的系の集合

学習データ・検証・微調整の訓練・テストデータは，$d_b=2$の標準の手順（EXP-0028，EXP-0031，EXP-0034）と同じ目的系である．開発集合は本実験で新たに予約する（これまでの記録とスクリプトに現れない範囲であることを確認した）．

|---|---|---|---:|
| 学習データ | 10000000〜10009999 | 11000000〜11009999 | 10000 |
| 検証 | 10600000〜10600199 | 11600000〜11600199 | 200 |
| 微調整の訓練 | 10700000から | 11700000から | — |
| 開発（新設） | 9521000〜9521499 | 9531000〜9531499 | 500 |

### 4.2．手順（両系の種類で同じ．標準の手順）

1. **教師データ：** `oracle.py --latent-dim full --budget 500 --n-random 100 --search-seed 0`．
   - n5-d22222：20分割×500個（評価seed $10000000+500k$）．
   - n5-d33333：80分割×125個（評価seed $11000000+125k$，$k=0,\dots,79$）．
2. **教師あり学習：** attention（$d_{\mathrm{model}}=128$，4ヘッド，4層，FFN 256），対称性による拡張あり，300エポック，バッチ256，学習率$10^{-3}$，検証10%，seed 0〜2．
3. **微調整：** 2000反復，$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$，検証200個（50反復ごと），seed 0〜2．ワーカーはn5-d22222が8，n5-d33333が10．
4. **第1段（開発集合）：** $d_b=3$の教師あり学習後と微調整後（各3つ），$d_b=2$の微調整後（EXP-0031，EXP-0034の各3つ．評価のみ）を開発集合で評価し，5節の第1段を記録する．
5. **第2段（テストデータ，本実験で1回だけ）：** $d_b=3$の6つのネットワーク（系の種類ごと）をテストデータで評価する．$d_b=2$は既存のテストデータの評価を使う．

### 4.3．実行前の確認

- **環境の確認（教師データを作る機械ごと）：** $d_b=3$の設定でテストデータの先頭20個を予算2で探索し，線形パスのステップ数が，$d_b=2$のネットワークの既存のテストデータの評価（EXP-0031，EXP-0034のseed 0の`evaluation_test*`の`Linear`の行）と完全に一致すること．
- **教師データの照合：** 1万個の線形パスのステップ数が，EXP-0028の$d_b=2$の教師データ（同じ目的系）と一致すること．

### 4.4．比較と報告する値

- 比較は`compare_runs.py`（3つのネットワークのステップ数を目的系ごとに平均し，目的系ごとに対応をとったブートストラップ，95%区間，2000回）．
- 主な比較：系の種類ごとに，$d_b=3$の微調整後 − $d_b=2$の微調整後．
- 補助の値：教師データの削減率と$d_b=2$の教師データとの差（目的系ごとに対応をとったブートストラップ），教師あり学習後の削減率，微調整の検証での削減率の推移と最良の反復，各段階の所要時間．

## 5．判断基準（実行前に固定）

差は「$d_b=3$の削減率 − $d_b=2$の削減率」（ポイント）で，正なら$d_b=3$の方が良い．判定はEXP-0047と同じ．

| 判定 | 条件 |
|---|---|
| 良い | 差が+1.0ポイント以上で，95%区間が0を含まない |
| 悪い | 差が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

**第1段（開発集合）：** 系の種類ごとに独立に判定する（多重比較の補正はしない）．

| 結果 | 判断（ユーザーに提案すること） |
|---|---|
| 両系の種類で「良い」 | n4-d3333を含め，n4・n5では$d_b=3$を標準の手順にする．残りの系の種類（n2〜n4の残り）にも$d_b=3$を広げる |
| 一方だけ「良い」 | 「良い」系の種類だけ$d_b=3$に切り替え，差が出る条件を調べる |
| どちらも「差なし」か「悪い」 | n5では$d_b=2$を続ける．n4-d3333の結果との違いの原因を調べる |

- 判断は開発集合だけで行う．テストデータの結果を見て判断を変えることはしない．

**第2段（テストデータ）：** 第1段の結果によらず，$d_b=3$の値を求める．報告の表（n5の$d_b=3$）に載せる値は，微調整後の値とする．テストデータの比較も同じ規則で判定して記録する．
