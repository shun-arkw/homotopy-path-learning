# EXP-0057：追跡をさらに大胆にしたとき，線形パスと学習したパスのどちらが解を取りこぼしやすいか

> 本記録の1〜6節は，実験の実行前（2026-10-18 JST）に書いた事前登録である．結果を見た後に1〜6節を変更する場合は，変更した箇所と理由を明記する．

## 1．基本情報

- 実験ID：EXP-0057
- 状態：Planned（事前登録）

## 2．目的

- これまでの評価では，学習したパスの利点を「同じ追跡の設定で追跡したときの，線形パスに対するステップ数の削減率」で測ってきた．この指標は，解の取りこぼしを見ていない．
- 実際に使うときに大事なのは，すべての解を見つけられる設定で，どれだけ少ないステップで済むかである．追跡を大胆にすると（1歩を大きくすると），線形パスが解を取りこぼし始めるかもしれない．そのとき学習したパスが取りこぼさずに少ないステップで済むなら，学習したパスの価値は，削減率が示すより大きい．
- EXP-0053では`β_ω_p`を0.8まで下げたが，2〜5変数の8つの系の種類で，線形パスと学習したパスのどちらにも取りこぼしはなかった．EXP-0056では，6変数・各3次の開発集合の1つの目的系で，`β_ω_p`=0.8の線形パスが解を1つ取りこぼした（同じ目的系で，学習したパスは取りこぼさなかった）．1件だけなので，どちらが取りこぼしやすいかは分からない．
- 本実験では，学習し直さずに`β_ω_p`を0.8から0.1まで下げて，線形パスと学習したパスの取りこぼしを数える．次の2つを調べる．
  1. 同じ追跡の設定で，学習したパスは線形パスより取りこぼしにくいか．
  2. それぞれが取りこぼさない範囲で最も大胆な設定を使うと，学習したパスのステップ数の利点（削減率）はどう変わるか．

## 4．方法（事前登録）

### 4.1．追跡の設定

新しい追跡の設定から，`β_ω_p`だけを0.8，0.5，0.3，0.2，0.1の5つに変える．ほかの値（上限なし，最初の1歩の幅の上限0.05，予測子は1次の微分だけ，`a`，`β_a`，`β_τ`など）は変えない．学習し直さない（ネットワークはすべて`β_ω_p`=0.8で微調整したもの）．

- 試運転（n2-d22の30個，n6-d333333の2個）では，`β_ω_p`を0.3より下げてもステップ数はほとんど変わらなかった．ステップ幅が`β_ω_p`以外の制限（予測が信頼できる範囲など）で決まるようになるためと考えられる．取りこぼしが`β_ω_p`を下げても増えない可能性がある．

### 4.2．取りこぼしの判定

- 参照の解：目的系ごとに，線形パスを慎重な設定（予測子は1次の微分だけ，HC.jlの`CONSERVATIVE_TRACKER_PARAMETERS`と同じ`β_ω_p`=4.0と`β_τ`=0.25，`max_step_size`=0.05）で追跡した終点．EXP-0053〜0056と同じ．`eval_beta.py`では，これらの値をすべて明示する．
- 参照の解が，すべてのパスで追跡に成功し，互いに相対誤差$10^{-6}$より離れているとき（`ref_ok`），その目的系を取りこぼしの判定に使う．満たさない目的系は記録し，取りこぼしの判定から除く．Pham系の解はちょうどパスの数だけあるので，`ref_ok`の目的系では，参照の解はすべての解の集合である．
- 線形パスと学習したパスのそれぞれで，参照の解のうち，どの終点からも相対誤差$10^{-6}$以内にないものの数を数える．

### 4.3．評価の手順

1. 開発集合（各500個）：10の系の種類×5つの`β_ω_p`の50個のプロセス（`eval_beta.py`）を，24個ずつ並列に実行する．
2. 環境の確認：`β_ω_p`=0.8の開発集合の評価が，既存の評価（2〜5変数はEXP-0055の「微調整だけをやり直した場合」の開発集合の評価，6変数はEXP-0056の「新しい設定で微調整・新しい設定で評価」）と，線形パスと学習したパスの受理と棄却のステップ数で，500個すべてで完全に一致すること．一致しなければテストデータの評価に進まずに止める．
3. 開発集合での結果と判断（5節）を記録に書く．
4. テストデータ（各500個）で，同じ50個を1回だけ評価する．5節の$\beta^*$は開発集合で決めたものを使う．

### 4.4．報告する値

系の種類と`β_ω_p`ごとに：

- 線形パスと学習したパスの1本あたりの平均ステップ数$J$（受理と棄却の合計．学習したパスは目的系ごとに3つのネットワークで平均），削減率（$(1-\bar J_\text{学習}/\bar J_\text{線形})\times100$），棄却されたステップの割合．
- 追跡に失敗したパスの数，取りこぼした解の数，取りこぼしの割合（線形パスと学習したパスのそれぞれ）．
- 取りこぼしの割合の差（線形パス − 学習したパス，ポイント）と95%区間．目的系ごとに対をとったブートストラップ（2000回，`default_rng(0)`を1回作り，系の種類は`summary.py`の順，`β_ω_p`は0.8から順に使う）．
- $\beta^*$（5節）と，取りこぼしをそろえた削減率．

## 5．判断基準（実行前に固定）

**取りこぼしの判定（系の種類ごと）：**

| 判定 | 条件 |
|---|---|
| 学習したパスのほうが取りこぼしにくい | ある`β_ω_p`で，取りこぼしの割合の差（線形 − 学習）が正で95%区間が0を含まない．かつ，差が負で95%区間が0を含まない`β_ω_p`がない |
| 学習したパスのほうが取りこぼしやすい | 上の逆 |
| 差なし | どの`β_ω_p`でも95%区間が0を含む |
| 混在 | 正と負の両方がある |

**取りこぼしをそろえたステップ数の比較：**

- $\beta^*$：線形パスと学習したパスのそれぞれで，その`β_ω_p`と，それより大きい格子のすべての`β_ω_p`で，開発集合で追跡の失敗も取りこぼしも0である（学習したパスは3つのネットワークのすべてで）ような，最も小さい`β_ω_p`．0.8でも0でなければ「なし」．
- 取りこぼしをそろえた削減率：$(1-\bar J_\text{学習}(\beta^*_\text{学習})/\bar J_\text{線形}(\beta^*_\text{線形}))\times100$．
- これと，`β_ω_p`=0.8での削減率（両方とも0.8）の差を，4.4節と同じブートストラップで求め，EXP-0055と同じ規則で判定する：差が+1.0ポイント以上で95%区間が0を含まなければ「良い」（取りこぼしをそろえると，学習したパスの利点が増える），−1.0ポイント以下で0を含まなければ「悪い」，それ以外は「差なし」．

**全体の読み方（記述的）：**

- 「学習したパスのほうが取りこぼしにくい」系の種類があり，「取りこぼしやすい」系の種類がなく，テストデータでも同じ向きなら，「追跡を大胆にしても，学習したパスは線形パスより解を取りこぼしにくい」と書く．
- 線形パスに取りこぼしがほとんど起きない場合（5つの`β_ω_p`のすべてで，10の系の種類の合計で取りこぼしのある目的系が5個未満）は，「`β_ω_p`を0.1まで下げても，線形パスはほとんど取りこぼさなかった．この方法では差を調べられなかった」と書く．その場合，`β_ω_p`以外のパラメータ（`β_τ`や`a`など）で追跡をさらに大胆にするか，目的系を増やすかを，ユーザーと決める（本実験では行わない）．
- 判断は開発集合だけで行う．テストデータの結果を見て判断を変えることはしない．テストデータでも同じ規則で判定し，記録する．

## 6．中断の条件

- 4.3節の環境の確認で，ステップ数が1つでも一致しない場合．
- 追跡がほとんど進まない（最大ステップ数で打ち切られる）パスが多発し，評価が終わらない場合．
- コンテナが止まった場合．
- 判断基準を，結果を見てから変えることはしない．
