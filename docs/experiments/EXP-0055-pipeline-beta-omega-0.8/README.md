## 2．目的

- EXP-0053で，学習し直さずに追跡を新しい追跡の設定に変えると，線形パスも学習したパスもステップ数が約4分の1になった．8つの系の種類の開発集合とテストデータで，追跡の失敗も解の取りこぼしもなかった．
- 一方，線形パスに対する削減率は，4つの系の種類で2.7〜3.7ポイント下がった．ネットワークは今の追跡の設定で教師データを作り，微調整したものである．
- 本実験では，教師データ・教師あり学習・微調整をすべて新しい追跡の設定で行い，次の3つを調べる．
  1. 新しい追跡の設定は，探索や微調整で試す大きく曲がった係数パスでも安全か（解の取りこぼし）．探索も微調整もステップ数を最小にしようとするので，取りこぼした（別の解のパスへ乗り移った）係数パスを「良い係数パス」として選んでしまう危険がある．
  2. 新しい追跡の設定で学習し直すと，削減率は今の標準（今の追跡の設定で学習し，今の追跡の設定で評価）と同じくらいに戻るか．
  3. 教師データ作りと微調整の時間はどれだけ短くなるか．

## 4．方法（事前登録）

### 4.1．取りこぼしの判定

- 目的系ごとに，線形パスを慎重な設定（予測子は1次，HC.jl の`CONSERVATIVE_TRACKER_PARAMETERS`，`max_step_size`=0.05）で追跡した終点を参照の解とする（EXP-0053の4.2節と同じ）．参照の解がすべて追跡に成功し，重複がないことも確かめる．
- 係数パスを追跡した終点のどれからも相対誤差$10^{-6}$以内にない参照の解の数を，「取りこぼした解」の数とする．

### 4.2．第0段：安全の確認（学習データの目的系だけを使う）

1. **既存の教師データの係数パス：** 8つの系の種類で，今の$d_b=3$の教師データ（3節）の先頭500個の目的系について，教師データの係数パス（探索で見つけた中間制御点）を，今の追跡の設定と新しい追跡の設定の両方で追跡し，ステップ数，失敗，取りこぼしを記録する．
2. **探索：** n4-d3333とn5-d33333の学習データの先頭20個で，探索（予算500．4.3節と同じ設定）を今の追跡の設定と新しい追跡の設定で行い，目的系1つあたりの時間を比べる．新しい追跡の設定で見つかった係数パスの取りこぼしも調べる．2つの設定の探索は同時に，同じ数のプロセスで行う．
3. **進む条件：** 1と2の新しい追跡の設定で，失敗したパスも取りこぼした解も0であること．満たさなければ第1段に進まず，結果を報告して判断を仰ぐ．

### 4.3．第1段：標準の手順（新しい追跡の設定）

各系の種類で，設定ファイル（`exp-0055-*-db3-bw08.yaml`）を使って次を行う．追跡の設定以外は，$d_b=3$の標準の手順と同じである．

1. **環境の確認：** 開発集合の先頭20個を予算2で探索し，線形パスのステップ数が，EXP-0053で新しい追跡の設定で評価した線形パスのステップ数（`outputs/EXP-0053/dev/{系の種類}-B0.8.csv`の`Linear`の行）と完全に一致すること．
2. **教師データ：** `oracle.py --latent-dim full --budget 500 --n-random 100 --search-seed 0`，20分割×500個（評価seedは学習データの先頭$+500k$）．
3. **教師データの確認：** 1万個すべてについて，教師データの係数パスを新しい追跡の設定で追跡し直し，失敗と取りこぼしを数える．線形パスのステップ数（`linear_cost`）が，同じ目的系をスクリプトで新しい追跡の設定で追跡した値と一致することも確かめる．
4. **教師あり学習：** attention（$d_{\mathrm{model}}=128$，4ヘッド，4層，FFN 256），対称性による拡張あり，300エポック，バッチ256，学習率$10^{-3}$，検証10%，seed 0〜2．
5. **微調整：** 2000反復，$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$，検証200個（50反復ごと），seed 0〜2．
6. 各段階の開始と終了の時刻，プロセス数（ワーカー数）を記録する．

### 4.4．第2段：開発集合での比較

次の3つを，開発集合の500個で評価する（失敗と取りこぼしも記録する）．

| 名前 | ネットワーク | 評価の追跡の設定 |
|---|---|---|
| 今の標準 | 今の$d_b=3$の微調整後（3節） | 今の追跡の設定（EXP-0053の評価を使う） |
| 学習し直さない場合 | 今の$d_b=3$の微調整後（3節） | 新しい追跡の設定（EXP-0053の評価を使う） |
| 学習し直した場合 | 本実験の微調整後（各3つ） | 新しい追跡の設定 |

本実験の教師あり学習後（各3つ）と，4.7節の「微調整だけをやり直す場合」（各3つ）も，新しい追跡の設定で評価する．

### 4.5．第3段：テストデータ（本実験で1回だけ）

- 学習し直した場合（微調整後と教師あり学習後）と，微調整だけをやり直す場合（4.7節）を，8つの系の種類のテストデータで評価する．今の標準と学習し直さない場合は，EXP-0053のテストデータの評価を使う．

### 4.7．追加の候補：微調整だけをやり直す場合（2026-10-17 22:40 JST頃に追加）

- 各系の種類の今の$d_b=3$の教師あり学習後のネットワーク（今の追跡の設定の教師データで学習したもの．seed 0〜2）から，新しい追跡の設定で微調整だけをやり直す．
  - 教師あり学習のrun：n2-d22，n3-d222，n4-d2222はEXP-0051，n2-d33はEXP-0026，n3-d333はEXP-0021，n4-d3333はEXP-0047（予算500），n5の2つはEXP-0050の`*-db3-bc-attn-seed{0,1,2}*`．
  - 微調整の設定は4.3節の5と同じ（seed，検証と訓練の目的系も同じ）．`--allow-init-tracker-difference`を付ける．
- 4.4節の表に「微調整だけをやり直した場合」（新しい追跡の設定で評価）を加える．4.6節の主な比較と同じく，今の標準との削減率の差を求める．

### 4.6．報告する値

- 削減率（線形パスに対する．3つのネットワークのステップ数を目的系ごとに平均）と，学習したパスの平均ステップ数$\bar J$．
- 比較の差と95%区間（目的系ごとに対応をとったブートストラップ，2000回）：
  - **主な比較**：学習し直した場合の削減率 − 今の標準の削減率．
  - 補助の比較：学習し直した場合 − 学習し直さない場合（削減率と，学習したパスの$\bar J$の相対変化）．
- 教師データの削減率（1万個）．教師あり学習後の削減率．微調整の検証での削減率の推移と最良の反復．
- 失敗と取りこぼしの数（教師データ，開発集合，テストデータ）．棄却ステップの割合．
- 各段階の時間と，これまでの$d_b=3$の標準の手順の時間（各実験の記録）との比較．プロセス数が違うので，CPU時間（時間×プロセス数）でも比べる．

## 5．判断基準（実行前に固定）

差は「学習し直した場合の削減率 − 今の標準の削減率」（ポイント）．判定はこれまでと同じ．

| 判定 | 条件 |
|---|---|
| 良い | 差が+1.0ポイント以上で，95%区間が0を含まない |
| 悪い | 差が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

**第2段の判断（開発集合，系の種類ごと）：**

| 結果 | 判断（ユーザーに提案すること） |
|---|---|
| 安全（教師データ・開発集合で失敗も取りこぼしも0）で，判定が「良い」か「差なし」 | その系の種類では，新しい追跡の設定の標準の手順を今後の標準にする |
| 安全でない，または判定が「悪い」 | その系の種類では，今の追跡の設定を続ける．原因を調べる |

- 4.7節の「微調整だけをやり直す場合」にも同じ規則を当てはめる（安全の条件は開発集合だけ）．学習し直した場合と微調整だけをやり直す場合の両方が条件を満たすときは，開発集合の削減率（点推定）が高い方を提案する．

- 8つの系の種類で判断が分かれた場合は，結果を報告して，標準をどうそろえるかをユーザーと決める．
- 判断は開発集合だけで行う．テストデータの結果を見て判断を変えることはしない．
- テストデータでも，同じ規則で判定して記録する．
