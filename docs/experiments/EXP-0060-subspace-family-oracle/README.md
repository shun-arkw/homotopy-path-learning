# EXP-0060：目的系をランダムな部分空間の族に限ったとき，探索（oracle）は線形パスに対してどれだけ改善するか（n4-d3333，n5-d33333）

> 本記録の1〜6節は，実験の実行前（2026-11-06 JST）に書いた事前登録である．結果を見た後に1〜6節を変更する場合は，変更した箇所と理由を明記する．

## 1．基本情報

- 実験ID：EXP-0060
- 状態：Planned（事前登録）
- 関連：ADR-0008（目的系を部分空間の族に限る設定），EXP-0059（目的系は一般のまま，行動をランダムな部分空間に絞った探索），EXP-0055（新しい追跡の設定，$d_b=3$）．計画の経緯は`docs/design/drafts/2026-11-05-subspace-family/plan.md`．
- 用語：
  - **新しい追跡の設定**：`β_ω_p`=0.8，1歩の幅の上限`max_step_size`=1.0，ほかは既定値．最初の1歩の幅の上限0.05，予測子は1次の微分だけ（EXP-0055〜0059と同じ）．
  - **族**：目的系の自由な係数を$\boldsymbol{c}_F=W\boldsymbol{u}$とする目的系の集まり（ADR-0008）．$W$は$m\times k$のランダムな複素行列で，列は正規直交（`family_seed`から作る）．$\boldsymbol{u}$は複素ガウス分布で，係数の大きさの2乗の平均を今の一様分布と同じ$2/3$にする．$m$は自由な係数の数（n4-d3333で20，n5-d33333で30）．
  - **一般（ガウス）**：$k=m$の族．自由な係数が独立な複素ガウス分布に従う．同じ生成器で$k$だけを変えた比較の基準．
  - **族の基底**：行動（中間の制御点の摂動）を$W$の像に限る基底（潜在次元$2k$，行動の次元$4k$）．**全次元の行動**：今と同じランダムな正方の基底（潜在次元$2m$，行動の次元$4m$）．
  - **探索（oracle）**：目的系ごとに，行動を直接探して追跡のステップ数$J$（受理と棄却の合計の，パス1本あたりの平均）を最小にする（`oracle.py`）．行動0（線形パス）と一様乱数の行動を合わせて`n_random`回評価し，残りを1/5成功則の進化戦略で探す．**予算**は$J$を評価する回数．
  - **改善量**$O(b)=(1-\overline{J^*(b)}/\bar J_{\text{線形}})\times100$（%）．$J^*(b)$は目的系ごとの先頭$b$回の評価の最小値（予算$b$の探索の結果），上の線は目的系の平均．

## 2．目的

- 目的系を部分空間の族に限ると学習が易しくなるかを調べる前に，族で次のことを確かめる．
  1. 族の目的系で，探索は線形パスに対してどれだけ改善するか．それは$k$でどう変わるか，一般（ガウス）とどう違うか．低い$k$の族で改善の余地がほとんどなければ，その族で学習を調べる意味は薄い．
  2. 族の目的系で，行動を$W$の像に絞った探索は，全次元の探索に比べて改善量をどれだけ保ち，どれだけ速く頭打ちになるか（EXP-0059の族版）．族では目的系も$W$の像の中にあるので，EXP-0059（目的系は一般）と結果が変わりうる．
  3. 族ごとの線形パスの追跡の安全（失敗，取りこぼし）．
- 変数の数を増やしたとき（n4→n5，同じ各3次）に，同じ$k$で何が変わるかも見る．
- 学習（教師あり学習と微調整）は本実験では行わない．

## 4．方法（事前登録）

### 4.1．環境の確認と学習の前の確認（`run_oracle.sh`の1と2）

1. 環境の確認：一様分布のベースの設定で，EXP-0058の開発集合の先頭5つの目的系（n4-d3333は9310000〜，n5-d33333は9531000〜）の線形パスの受理・棄却のステップ数が，EXP-0058と完全に一致すること（`envcheck.py`）．一致しなければ止める．
2. 26個の族の開発集合で，線形パスと参照の解（EXP-0058と同じ慎重な追跡：`β_ω_p`=4.0，`β_τ`=0.25，`max_step_size`=0.05）を計算する（`eval_family.py`）．
3. 記録する値（`oracle_stage0_summary.py`）：除外する目的系の数，線形パスの$\bar J$と取りこぼし，目的系の係数の最大の$|c|$の分布，$W$の行のノルムの2乗の最大と最小の比（係数ごとの分散のばらつき）．
4. **除外の規則**：参照の解が条件を満たさない（`ref_ok`=0：慎重な追跡で失敗したパスがあるか，終点どうしが相対誤差$10^{-6}$以内で重なる）か，新しい追跡の設定の線形パスで追跡に失敗したパスがある目的系は，その族の改善量の計算から除く（失敗のペナルティ$10^5$で平均$J$がその目的系で決まってしまうため）．除外の数は記録するだけで，実験は止めない．
5. 線形パスで追跡に失敗した目的系は，4.3節の「救えた目的系」で別に数える．

### 4.2．探索（`run_oracle.sh`の3）

- 族ごとに，族の基底と全次元の行動の2通り（一般（ガウス）は全次元の行動だけ）．`oracle.py --budget 1000 --n-random 100 --search-seed 0`．系の種類あたり25通り，計50通り（225個のjob）．
- 探索は総予算に依存しない（乱数の行動の後，1/5成功則で幅を変えるだけ）ので，予算100，300，500の値は，予算1000の実行の`oracle_cost_traces.npy`の先頭から読む．

### 4.3．報告する値（`oracle_summary.py`）

系の種類と族ごとに：

- 除外の数，線形パスの$\bar J$．
- 族の基底と全次元の行動の改善量$O(b)$（$b$=100，300，500，1000）．一般（ガウス）は全次元の行動．
- 保持率$R=O_{\text{族の基底}}(1000)/O_{\text{全次元}}(1000)$と95%区間（目的系についての対をとったブートストラップ．2000回，`default_rng(0)`を1回作り，`targets.txt`の順に使う）．
- 必要な予算$B^*$：族の基底の$\overline{J^*(b)}$が，全次元の$\overline{J^*(500)}$以下になる最小の$b$（1000以内に届かなければ「未到達」）．
- 1目的系あたりの時間，最良の行動が箱の境界に達した割合（`best_action_max_abs`≥0.999），最良の行動で追跡に失敗したパスを含む目的系の数．
- **救えた目的系**（`rescue_check.py`）：線形パスで追跡に失敗した目的系ごとに，族の基底と全次元の行動の探索の最良の行動で追跡し直し，失敗したパスがなく，終点がすべて区別できる（相対誤差$10^{-6}$）なら「救えた」とする．Pham型の系の解はちょうど$\prod_id_i$個なので，これは解をすべて追跡できたことを意味する（参照の解が作れなかった目的系でも判定できる）．族ごとに，線形パスで失敗した目的系の数と，探索で救えた数を記録する（記述の値）．

## 5．判断基準（実行前に固定）

系の種類と$k$ごとに：

- **改善の保持**：3つの$W$のすべてで$R\ge0.85$．
- **速さ**：3つの$W$のすべてで$B^*\le250$（全次元の予算500と同じ改善量に，その半分以下の予算で届く）．

全体の読み方（記述）：

- 族の改善量$O_{\text{全次元}}(1000)$と$k$の関係，一般（ガウス）との違い，n4とn5の違いを記述する．どの$k$でも改善量が一般（ガウス）の半分未満なら，「この族は線形パスで十分に易しく，学習の比較には向かない」と書く．
- 改善の保持と速さの両方を満たす$k$があれば，「族では，行動を$W$の像に絞ると，改善量を保ったまま探索が速くなる」と書く（EXP-0059の一般の目的系では速くならなかった）．
- 結果を見て，次の学習の実験（族の選び方，$k$）を決める．判断基準の数値（0.85，250）は事前に決めた目安であり，結果を見て変えない．
