### 1.1．必要なコードの変更（実行前に行い，テストを通してからコミットする）

HomotopyContinuation.jl（以下 HC.jl）の予測子は，(2,1)型の Padé 近似（有理関数による近似）を作るために，解のパス$x(t)$の$t$についての3次までのテイラー係数を，ホモトピー$H(x,t)$のテイラー係数（`ModelKit.taylor!`）から計算する．今の実装は次の2点でこれに応えていない．

- 追跡用のホモトピー（`julia/src/tracking.jl`の`_homotopy_for_tracking`）は，2次以上のテイラー係数に0を返す．そのため予測子は実質的にオイラー法になっている．
- `julia/src/bezier_homotopy.jl`の`ModelKit.taylor!`は，2次以上でも，$x$のテイラー展開の項（`tx`の1次以上の項）を使わず，$x$を定数として係数の微分だけを計算している．これは$H(x(t),t)$のテイラー係数としては正しくない．

次の変更を行う．

- `ModelKit.taylor!`を，$H\bigl(x(t),t\bigr)$の$k$次のテイラー係数（$x(t)$は`tx`で与えられるテイラー展開）を正しく計算するように直す（$k=1,2,3$）．係数パスはベジェ曲線なので，係数の$t$についての微分は$d_b$次を超えると0になるが，$x$の展開の項は残る．
- 追跡の設定に，予測子に渡すテイラー係数の最高次数（1または3）を選ぶ項目を加える．**既定は1で，今とまったく同じ追跡になる**（既存のrunの`config.yaml`はそのまま読める）．
- テスト：
  - 同じ多項式系とベジェ曲線の係数パスを HC.jl の記号計算（`ModelKit`の`Homotopy`）で作ったホモトピーを参照とし，ランダムな点とテイラー展開で，$k=1,2,3$の`taylor!`の値が相対誤差$10^{-10}$以内で一致すること（n2とn3，各式の次数2と3，$d_b=2$と3）．
  - 次数3を選んだとき，小さい系で全部の解が重複なく得られること．
  - 次数1を選んだとき（既定），追跡の結果が変更前と一致すること．
  - `python3 -m pytest -q`と Julia のテストを参照Dockerで実行する．
- 設計文書（`docs/design/implementation/julia_homotopy.md`）の`ModelKit.taylor!`と追跡の設定の記述を更新する．
- EXP-0053の変更（`TrackerParameters`を渡せるようにする）と同じコミットにまとめてよい．

## 2．目的

- 報告（2026-10-17）の5.2節のとおり，今の実装では予測子が実質的にオイラー法で，予測が信頼できる範囲$\tau$も特異点までの距離を表していない．HC.jl と論文（Timme）が想定する使い方では，(2,1)型の Padé 近似（次数4）で予測し，$\tau$で特異点の近くでは慎重に，遠くでは大きく進む．
- 高次の予測子は同じステップ幅での予測の誤差が小さいので，ステップ数が減ると期待される．$\tau$が働くので，パスの乗り移りにも強くなるはずである．一方，1ステップあたりの計算（2次と3次のテイラー係数と，連立方程式の解き直し2回）が増えるので，ステップ数が減っても時間が減るとは限らない．
- 今のコードのコメントには，「線形の係数パスで Padé 予測子が不安定になることがあった」とある（古いバージョンの HC.jl での記述）．これが今の HC.jl と正しいテイラー係数で起きるかも確かめる．
- 本実験では，学習と微調整をし直さずに，予測子に渡す次数と追跡のパラメータを変えて，ステップ数・削減率・追跡の失敗・解の取りこぼし・時間を調べる．安全な設定の中で最もステップ数の少ないものを開発集合で選び，テストデータで1回だけ確かめる．

## 5．判断基準（実行前に固定）

EXP-0053の5節と同じ規則を，本実験の次数3の4つの設定に適用する．

- **安全の条件：** 8つの系の種類のすべてで，開発集合の線形パスと3つのネットワークのパスのどれにも，追跡に失敗したパスと取りこぼした解が1つもない．
- **第1段の選択：** 安全な次数3の設定のうち，$S=\frac18\sum\bar J_{\text{学習}}(\text{その設定})/\bar J_{\text{学習}}(\text{今の設定})$が最小のものを選ぶ．最小値との差0.01以内の設定が複数あるときは，次数3・`CONSERVATIVE`，次数3・上限0.05，次数3・上限なし，次数3・`FAST`の順（慎重な順）で先にあるものを選ぶ．安全な設定がなければ「選ばれる設定なし」．

- 時間が増える場合でも，選択の規則は変えない（$S$はステップ数で決める）．時間を含めてどの設定を標準にするか，その設定で微調整し直すかは，結果を報告してユーザーが判断する．

- **予測子の次数を3にすると，ステップ数は大きく減った**（既定のパラメータで上限を外した設定で，線形パスは−70〜−79%，学習したパスは−65〜−72%）．追跡の失敗はどの設定でもなく，コードのコメントにあった「線形の係数パスでの不安定さ」は見られなかった．
- **一方，学習したパスの利点はほとんど消えた．** 削減率は7〜15%になった（今の設定では22〜37%）．予測子の次数を上げると線形パスが特に大きく減り，学習したパスとの差が縮んだ．ネットワークは次数1の追跡で微調整したもので，次数3の追跡に合ったパスにはなっていない．
- **1ステップが重くなる**（大きい系で約1.8〜2.0倍）．そのため，ステップ数では次数3・上限なしとEXP-0053の`β_ω_p`=0.8・上限なしは近い（線形パスで同程度）が，時間では`β_ω_p`=0.8の方がすべての系の種類で速かった（例：n5-d33333の学習したパスで`β_ω_p`=0.8は13.9 ms，次数3・上限なしは28.0 ms）．
- **`FAST`と組み合わせると，解の取りこぼしが起きた**（n5-d33333の開発集合で2つの目的系）．予測子が本来どおり働いても，安全係数を下げすぎるとパスの乗り移りは起きる．
- 判断（ユーザーに提案すること）：次数3の予測子を使う場合は，その追跡でネットワークを微調整し直さないと学習したパスの利点が出ない．ただ，時間ではEXP-0053の`β_ω_p`=0.8・上限なしの方が有利なので，次数3を採るかは慎重に決める必要がある．

### 7.6．訂正（2026-10-17，実験の後に判明）

- `outputs/EXP-0053/scripts/eval_arm.py`（EXP-0053と共通）は，参照の解を求める環境（慎重な設定）と評価する環境（比べる設定）を，同じプロセスの中で作っていた．同じプロセスの中で作った環境は，Julia側の追跡の状態（ホモトピーと追跡の設定）を1つ共有しており，最後に作った環境の追跡の設定が，すべての環境の追跡に使われる．このことは，EXP-0055の準備中（2026-10-17）に，同じスクリプトの構成で設定ごとの結果が一致してしまうことから気づき，確かめた．
- そのため，参照の解は，4.2節に書いた「慎重な設定（`CONSERVATIVE`，上限0.05）で追跡した線形パスの終点」ではなく，**比べる設定と同じ設定で追跡した線形パスの終点**だった．
  - 線形パスの「取りこぼした解」は，自分自身と比べているので常に0になり，意味を持たない．EXP-0053の7.2節の「今の設定の線形パスの終点は，すべての目的系で参照の解と一致した」も同じ理由で意味を持たない（EXP-0053の7.6節で取り消した）．
  - ただし，参照の解の確認（すべてのパスで追跡に成功し，終点に重複がないこと）は，すべての設定・系の種類・目的系で満たされていた（開発集合とテストデータ）．Pham系の解はちょうど$N$個（$N$はパスの数）なので，**比べたどの設定でも，線形パスはすべての解に着いていた**．学習したパスの取りこぼしが0であることは，学習したパスもすべての解に着いたことを意味する．
  - したがって，安全の条件（失敗も取りこぼしもないこと）の判定と，選んだ設定の結論は変わらない．変わるのは，取りこぼしを判定した基準（参照の解）の作り方だけである．
- ステップ数，削減率，時間には影響しない（評価する環境は，最後に作られたので正しい設定で追跡していた）．
- 次数3・`FAST`の取りこぼし（n5-d33333の開発集合で2つの目的系）は，学習したパスが，同じ設定の線形パスの重複のない$N$個の終点のうち1つに着かなかったもので，本当の取りこぼしである．
- EXP-0055からは，使う環境の追跡の状態を，追跡の前に毎回初期化し直す（`outputs/EXP-0055/scripts/label_paths.py`）．
