## 2．目的

- EXP-0028の予備調査で，n5-d33333のoracleの改善余地は$-16.41\%$（予算3000）と，n5-d22222（$-29.69\%$）より小さかった．予算1000から3000に増やしても，$-15.67\%$から$-16.41\%$とほとんど伸びなかった．
- これは，改善余地が本当に小さいのではなく，oracleの探索（ゼロ行動から始める(1+1)進化戦略）が局所的に行き詰まっているだけかもしれない．n3-d333では，学習した方策が予算3000のoracleを上回っており（EXP-0021），次数3の系でoracleの探索が弱いことが分かっている．
- 探索を強めると，oracleの値がどれだけ改善するかを調べる．

## 3．多項式系

EXP-0028と同じ（n5-d33333，$f_i=x_i^3+\sum_{j=1}^5a_{i,j}x_j+a_{i,6}$，$N_{\mathrm{path}}=243$）．

## 4．方法（事前登録）

- 問題：EXP-0028の評価問題のうち先頭20問題（評価seed 9510000〜9510019）．
- 比べる探索（いずれも全次元，`oracle.py`，最初の100評価はゼロ行動と一様乱数）：
  1. **基準：** EXP-0028の予算3000，探索seed 0（既存の結果）．
  2. **多点スタート：** 探索seed 0〜4の予算3000の探索（seed 0は既存，seed 1〜4を新たに実行）のうち，問題ごとに最良の値をとる（合計15000評価）．
  3. **長い探索：** 探索seed 0，予算10000の1回の探索．
- 1問題ずつ別のプロセスで実行する．

## 5．判断基準（実行前に固定）

- 2．または3．の$\Delta J$（20問題の平均$J$での値）が，1．より2ポイント以上小さい → 今のoracleは，n5-d33333で探索が足りていない．
- 問題ごとに，2．と3．で1．より良くなった問題の数と，改善量の分布も報告する．
