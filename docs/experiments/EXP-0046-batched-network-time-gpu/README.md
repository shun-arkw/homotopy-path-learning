# EXP-0046：複数の目的系をまとめたときのネットワークの計算時間（GPU）

> 本記録の1〜6節は，実験の実行前（2026-10-16 JST）に書いた事前登録である．結果を見た後に1〜6節を変更する場合は，変更した箇所と理由を明記する．

## 1．基本情報

- 実験ID：EXP-0046
- 状態：Planned（事前登録）
- 実行環境：メインの作業環境の参照Docker`homotopy-continuation`（作り直し後．Dockerのcgroupドライバをcgroupfsに変更した後）．GPUはRTX A5000 1枚．CPU側はスレッドの環境変数を1にする．他の計算がない状態で計測する．
- コードの変更：なし．計測は実験フォルダに置くスクリプト（`outputs/EXP-0046/scripts/batch_forward_gpu.py`）で行う．EXP-0045のスクリプトと同じ処理で，ネットワークをGPUに置く点だけが違う．

## 2．目的

- EXP-0045で，CPUでまとめて計算すると，目的系1つあたりのネットワークの計算時間は$B=1$の約1/3〜1/8になった．
- GPUでは，$B$個の目的系を1回の計算でまとめて処理する時間が$B$にほとんどよらず，1回あたり約1 ms以下で済む可能性がある．これを確かめる．

## 3．多項式系と，ネットワーク

EXP-0045と同じ（標準の手順のネットワーク，seed 0，全8系の種類，各系の種類のテストデータ500個の係数．追跡はしない）．

## 4．方法（事前登録）

- バッチの大きさ$B\in\{1,10,100,500\}$．500個の目的系を$B$個ずつ$500/B$組に分ける．
- 1組の計測：係数から入力の配列を作る（CPU）→GPUへ送る→ネットワークの計算（勾配なし）→出力をCPUへ戻してNumPyの配列にする，までの時間．CPUへ戻す処理はGPUの計算の完了を待つので，待ち時間も含む．
- 最初にGPUの準備のために20回空で計算する．その後，各$B$でウォームアップ3回，各組を5回測り中央値をとる．
- 報告する値：1組あたりの時間（ms）と，目的系1つあたりの時間（＝全組の中央値の和÷500）．

## 5．判断基準（実行前に固定）

- 記述的な計測であり，合否の基準は設けない．
- 系の種類ごとに，$B$ごとの1組あたりの時間と目的系1つあたりの時間を，EXP-0045（CPU）と並べて表にする．

## 6．中断の条件

- 計測中に他の計算（他の利用者のGPUの計算を含む）が動いていることが分かった場合は，その系の種類を測り直す．
- GPUの出力とCPUの出力（EXP-0045と同じ計算）の最大絶対差が$10^{-4}$を超える場合は止めて報告する．

## 7．計算量の見積もり

数分．
