# EXP-0049：n5から転用したネットワークをn6-d333333で微調整する

> 本記録の1〜6節は，実験の実行前（2026-10-16 22:30 JST頃）に書いた事前登録である．結果を見た後に1〜6節を変更する場合は，変更した箇所と理由を明記する．

## 1．基本情報

- 実験ID：EXP-0049
- 状態：Planned（事前登録）
- 設定ファイル（本実験で追加）：`experiments/multivariate_pham/configs/exp-0049-n6-d333333-db2.yaml`．`exp-0048-n6-d333333-db2.yaml`との違いは，`experiment.id`と，微調整の最後に自動で行う評価の目的系（`evaluation.seed`を9570000から9572000へ，`random_action_seed`を9570500から9572500へ）だけである．
  - 理由：`exp-0048-n6-d333333-db2.yaml`では`evaluation.seed`をテストデータの先頭（9570000）にしていた．このまま微調整すると，終了時の自動評価でテストデータの先頭100個を使ってしまう．EXP-0048では微調整も教師あり学習もしていないので，テストデータを余分に使ったことはない．9572000〜9572099は，これまでの記録とスクリプトに現れない範囲である．
  - 今後のn6の学習（教師あり学習・微調整）でも，同じ理由で`evaluation.seed`をテストデータ以外に変えた設定を使う．
- 実行環境：3つのseedを2台の機械で分けて実行する．どちらもEXP-0047が終わってから始める．
  - seed 0と1：外部サーバ（GPU 4台のサーバ）の参照Docker`homotopy-continuation`．CPUのみ．各15ワーカー．実行の直前に`git pull --ff-only`を行い，コミットがメインの環境と一致し，作業ツリーがcleanであることを確かめる．
  - seed 2：メインの作業環境の参照Docker`homotopy-continuation`．CPUのみ．20ワーカー．
  - 微調整の結果はワーカーの数によらない（EXP-0043で使った前提と同じ）．2台の機械の追跡のステップ数は，EXP-0047の教師データ1万個でも完全に一致した．
  - 開発集合とテストデータでの評価，比較はメインの環境で行う（サーバのrunは，評価に必要なフォルダだけを写す）．
- コードの変更：なし．

## 2．目的

- EXP-0048では，n5-d33333のネットワーク（標準の手順，3つ）を学習し直さずにn6-d333333へ転用し，テストデータで22.8%の削減になった．
- 本実験では，この転用したネットワークに，n6-d333333で微調整（標準の手順の③と同じ設定）だけを行う．教師データは作らない．
  - n6-d333333では1回の追跡に約0.5〜0.75秒かかり，教師データを標準の手順で作ると約2日かかる見込みである．微調整だけなら，その数分の1で済む．
  - 「n6で学習することで，転用からどれだけ伸びるか」を，教師データなしで測る．
- 本実験の値も，今後のn6専用のネットワークと比べる対象の1つにする．

## 3．多項式系

EXP-0048と同じn6-d333333（$n=6$，次数3，パスの数729，$d_b=2$，ずれの次元84）．

## 4．方法（事前登録）

### 4.1．出発点のネットワーク

EXP-0048のn5-d33333からの転用（3つ）：`outputs/EXP-0048/exp-0048-n6-d333333-db2-from-n5-d33333-seed{0,1,2}-20261016T120524Z`．

### 4.2．微調整

報告の標準の手順の③と同じ設定：2000反復，$K=32$，$P=4$，$\sigma=0.05$，学習率$10^{-4}$，$\lambda=0$．seedは出発点と同じ0〜2．

| 項目 | 値 |
|---|---|
| 検証 | seed 14600000〜14600199（200個，50反復ごと．EXP-0048 4.2節で予約した範囲） |
| 微調整の訓練 | seed 14700000から（反復ごとに32個．同上） |
| 採用する重み | 検証で最も良かった反復（標準の手順と同じ） |

### 4.3．評価と比較

- 3つの微調整後のネットワークを，EXP-0048と同じ開発集合（9571000〜9571499）とテストデータ（9570000〜9570499）で評価する（`evaluate.py`，各500個）．テストデータは本実験で1回だけ使う．
- 比べる相手：EXP-0048のn5-d33333からの転用（微調整前，3つ．既存の評価を使う）．
- 比較は`compare_runs.py`（3つのネットワークのステップ数を目的系ごとに平均し，目的系ごとに対応をとったブートストラップ，95%区間，2000回）．
- 報告する値：
  - テストデータと開発集合での削減率（3つの平均とseedごと），差（微調整後 − 転用）と95%区間．
  - 検証での削減率の推移（反復0，500，1000，1500，2000）と，最良の反復．
  - 微調整にかかった時間（seedごとの経過時間と，ワーカーの数）．

## 5．判断基準（実行前に固定）

差は「微調整後の削減率 − 転用の削減率」（ポイント，テストデータ）で，正なら微調整後の方が良い．

| 判定 | 条件 |
|---|---|
| 微調整で良くなった | 差が+1.0ポイント以上で，95%区間が0を含まない |
| 微調整で悪くなった | 差が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

- 参考：標準の手順の微調整は，教師あり学習の後から大きく伸ばした（n4-d2222のattentionで約9ポイント，EXP-0022）．ただし本実験の出発点はすでに微調整済みのネットワークなので，伸びは小さい可能性がある．
- 今後のn6専用のネットワークとの比較は，EXP-0048 5節と同じやり方で，本実験の微調整後のネットワーク（3つ）も比べる対象に加える．
