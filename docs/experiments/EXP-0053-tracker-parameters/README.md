# EXP-0053：追跡のステップ幅のパラメータ（`TrackerParameters`）を変えたときのステップ数（学習し直さない評価）

> 本記録の1〜6節は，実験の実行前（2026-10-17 20:20 JST頃）に書いた事前登録である．結果を見た後に1〜6節を変更する場合は，変更した箇所と理由を明記する．

## 1．基本情報

- 実験ID：EXP-0053
- 状態：Planned（事前登録）
- 関連：報告`docs/reports/2026-10-17-step-size-settings.md`，EXP-0052（上限`max_step_size`だけを緩めた評価），EXP-0054（予測子に高次の微分を渡す評価．本実験と並行して行う）．

### 1.1．必要なコードの変更（実行前に行い，テストを通してからコミットする）

今の多変数の実装は，HomotopyContinuation.jl（以下 HC.jl）の`TrackerParameters`を渡せない．次の変更を行う．

- `julia/src/api.jl`の`make_tracker_options`に，`TrackerParameters`の6つの値（`a`，`β_a`，`β_ω_p`，`β_τ`，`strict_β_τ`，`min_newton_iters`）を受け取る引数を加える．省略したときは HC.jl の既定値（`DEFAULT_TRACKER_PARAMETERS`．`strict_β_τ`は HC.jl と同じく$\min(0.75\beta_\tau,0.4)$）にする．
- Python の追跡の設定（`TrackerConfig`と設定ファイルの`tracker`の項）に，上の6つを省略可能な項目として加える．**省略したときは，今とまったく同じ追跡になる**（既存のrunの`config.yaml`はそのまま読める）．
- テスト：
  - Julia：引数を省略した`make_tracker_options`の`parameters`が`DEFAULT_TRACKER_PARAMETERS`と一致すること．値を与えたときに，その値が`TrackerParameters`に入ること．
  - Python：設定ファイルの読み込み（省略時の既定値，値の検証，不正な値の拒否），Julia への受け渡し．
  - `python3 -m pytest -q`と Julia のテストを参照Dockerで実行する．
- 設計文書（`docs/design/implementation/julia_homotopy.md`など，追跡の設定を記した箇所）に，追加した項目を書く．

## 2．目的

- 報告（2026-10-17）の5.3節では，n4以上の系の種類で，ステップ幅のほとんど（93〜96%）が，ニュートン法の収束範囲から決まる値$\Delta s_1$で決まっていた．$\Delta s_1$は`β_ω_p`に反比例し，`a`（`β_a`）を大きくすると大きくなる．多変数の実験では，これらは HC.jl の既定値のままである．
- 一方，今の実装では予測子が実質的にオイラー法で，予測が信頼できる範囲$\tau$が特異点までの距離を表していない（報告の5.2節）．そのため，`β_τ`はほとんど効かず，パスの乗り移りを防ぐ仕組みの一つが働いていない．`β_ω_p`を下げてステップ幅を大きくすると，乗り移りや追跡の失敗が起きる危険がある．
- 本実験では，学習と微調整をし直さずに，追跡のパラメータと上限だけを変えて，ステップ数・削減率・追跡の失敗・解の取りこぼし・時間がどう変わるかを調べる．安全な設定の中で最もステップ数の少ないものを開発集合で選び，テストデータで1回だけ確かめる．

## 4．方法（事前登録）

### 4.1．追跡の設定（腕）

どの腕でも，予測子は今の実装のまま（1次の微分だけ），最初のステップ幅の上限`max_initial_step_size`は0.05，そのほかの`TrackerOptions`（最小のステップ幅$10^{-12}$，最大のステップ数50000，拡張精度なし）は変えない．表にない`TrackerParameters`は既定値（`a`=0.125，`β_a`=1.0，`β_ω_p`=3.0，`β_τ`=0.4，`strict_β_τ`=0.3，`min_newton_iters`=2）．

| 腕 | 変える値 | `max_step_size` | 意味 |
|---|---|---:|---|
| A0 | なし | 0.05 | 今の設定（基準） |
| A1 | なし | 1.0 | 上限だけを外す（EXP-0052と同じ条件を開発集合で） |
| B2.0 | `β_ω_p`=2.0 | 1.0 | |
| B1.5 | `β_ω_p`=1.5 | 1.0 | |
| B1.0 | `β_ω_p`=1.0 | 1.0 | |
| B0.8 | `β_ω_p`=0.8 | 1.0 | 一変数の実験と同じ`β_ω_p` |
| C | `a`=0.2 | 1.0 | 論文（Timme）の実験の`a` |
| U | `β_ω_p`=0.8，`β_τ`=0.85，`strict_β_τ`=0.8，`min_newton_iters`=1 | 1.0 | 一変数の実験の設定 |

- ネットワークの出力（中間制御点）は，追跡の設定によらず同じである．スクリプトは，差し替えた設定と元の設定で入力が一致することを目的系ごとに確かめる．

### 4.2．参照の解（取りこぼしの判定に使う）

- 目的系ごとに，線形パスを，HC.jl の慎重な組（`CONSERVATIVE_TRACKER_PARAMETERS`：`β_ω_p`=4.0，`β_τ`=0.25）と`max_step_size`=0.05で追跡し，その終点を参照の解とする．
- 参照の解は，すべてのパスで追跡に成功し，互いに相対誤差$10^{-6}$より離れている（重複がない）ことを確かめる．満たさない目的系は記録し，その目的系は取りこぼしの判定から除く．
- 参照の解とA0の線形パスの終点が一致しない目的系の数も記録する．

### 4.3．第1段：開発集合での評価と選択

- 腕ごと・系の種類ごとに，開発集合の500個で，線形パスと3つのネットワークのパスを追跡する．
- 目的系ごとに記録する値：受理・棄却のステップ数，追跡に失敗したパスの数，取りこぼした解の数（参照の解のうち，どの終点からも相対誤差$10^{-6}$以内にないものの数），追跡にかかった時間（参考値．並列に実行するので，時間の比較には4.5節の計測を使う）．
- **環境の確認：** A0の結果は，既存の開発集合の評価（各runの`evaluation_dev<seed>`）と，線形パスも学習したパスも，受理・棄却のステップ数がすべての目的系で完全に一致すること．

### 4.4．第2段：テストデータでの評価（本実験で1回だけ）

- A0と，第1段で選んだ腕（5節）を，8つの系の種類のテストデータで評価する．記録する値は4.3節と同じ．
- A1がすでに選ばれた腕でない場合も，A1はテストデータでは評価しない（EXP-0052で$d_b=3$の3つの系の種類を評価済み）．
- 選ばれる腕がない場合（5節），第2段は行わない．

### 4.5．時間の計測

- A0と選んだ腕について，`experiments/multivariate_pham/timing.py`で，開発集合の先頭100個の目的系を解く時間を測る（1プロセス・1スレッド，ほかの実験を止めて，5回の中央値．報告の3節と同じ方法）．ネットワークは各系の種類のseed 0だけを使う．
- テストデータでは時間を測らない．

### 4.6．報告する値

- 腕・系の種類ごとに：線形パスと学習したパスの平均ステップ数$\bar J$（学習したパスは3つのネットワークの平均），削減率，棄却ステップの割合，失敗したパスの数，取りこぼした解の数（と，それが起きた目的系の数）．
- A0からの変化：学習したパスの$\bar J$の相対変化と，削減率の変化（ポイント）．どちらも95%区間（目的系ごとに対応をとったブートストラップ，2000回）．
- 時間（4.5節）：目的系1つあたりの追跡時間と全体の時間（ネットワークの計算を含む），A0からの変化率．

## 5．判断基準（実行前に固定）

**安全の条件：** ある腕が，8つの系の種類のすべてで，開発集合の線形パスと3つのネットワークのパスのどれにも，追跡に失敗したパスと取りこぼした解が1つもないとき，その腕を「安全」とする．

**第1段の選択（開発集合）：**
1. A0以外の腕のうち，安全なものを候補とする．候補がなければ「選ばれる腕なし」とし，第2段は行わない．
2. 候補ごとに$S=\dfrac18\sum_{\text{系の種類}}\dfrac{\bar J_{\text{学習}}(\text{腕})}{\bar J_{\text{学習}}(\text{A0})}$を求め，$S$が最小の腕を選ぶ．
3. $S$が最小値との差0.01以内の腕が複数あるときは，次の順で慎重な方を選ぶ：`β_ω_p`が大きい方，`a`が小さい方，U以外．

**第2段の判定（テストデータ）：** 選んだ腕のA0に対する削減率の変化を，系の種類ごとに次の規則で判定して記録する（EXP-0047以降と同じ）．学習したパスの$\bar J$の相対変化も記録する．

| 判定 | 条件 |
|---|---|
| 良い | 削減率の変化が+1.0ポイント以上で，95%区間が0を含まない |
| 悪い | 削減率の変化が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

- テストデータで失敗や取りこぼしが1つでもあれば，それを明記する（選択はやり直さない）．
- 選んだ設定を今後の標準にするかどうかは，結果を報告してユーザーが判断する．標準にする場合，その設定でネットワークを微調整し直すかどうかも別に判断する（本実験の範囲外）．

## 6．中断の条件

- 1.1節のテストが通らない場合．
- 4.3節の環境の確認で，A0の受理・棄却のステップ数が既存の評価と1つでも一致しない場合．
- 参照の解（4.2節）の条件を満たさない目的系が，どれかの系の種類で1%（5個）を超えた場合．
- コンテナの停止など，評価が途中で止まった場合．
- 判断基準を，結果を見てから変えることはしない．
