### 1.1．必要なコードの変更（実行前に行い，テストを通してからコミットする）

今の多変数の実装は，HomotopyContinuation.jl（以下 HC.jl）の`TrackerParameters`を渡せない．次の変更を行う．

- `julia/src/api.jl`の`make_tracker_options`に，`TrackerParameters`の6つの値（`a`，`β_a`，`β_ω_p`，`β_τ`，`strict_β_τ`，`min_newton_iters`）を受け取る引数を加える．省略したときは HC.jl の既定値（`DEFAULT_TRACKER_PARAMETERS`．`strict_β_τ`は HC.jl と同じく$\min(0.75\beta_\tau,0.4)$）にする．
- Python の追跡の設定（`TrackerConfig`と設定ファイルの`tracker`の項）に，上の6つを省略可能な項目として加える．**省略したときは，今とまったく同じ追跡になる**（既存のrunの`config.yaml`はそのまま読める）．
- テスト：
  - Julia：引数を省略した`make_tracker_options`の`parameters`が`DEFAULT_TRACKER_PARAMETERS`と一致すること．値を与えたときに，その値が`TrackerParameters`に入ること．
  - Python：設定ファイルの読み込み（省略時の既定値，値の検証，不正な値の拒否），Julia への受け渡し．
  - `python3 -m pytest -q`と Julia のテストを参照Dockerで実行する．
- 設計文書（`docs/design/implementation/julia_homotopy.md`など，追跡の設定を記した箇所）に，追加した項目を書く．

## 2．目的

- 報告（2026-10-17）の5.3節では，n4以上の系の種類で，ステップ幅のほとんど（93〜96%）が，ニュートン法の収束範囲から決まる値$\Delta s_1$で決まっていた．$\Delta s_1$は`β_ω_p`に反比例し，`a`（`β_a`）を大きくすると大きくなる．多変数の実験では，これらは HC.jl の既定値のままである．
- 一方，今の実装では予測子が実質的にオイラー法で，予測が信頼できる範囲$\tau$が特異点までの距離を表していない（報告の5.2節）．そのため，`β_τ`はほとんど効かず，パスの乗り移りを防ぐ仕組みの一つが働いていない．`β_ω_p`を下げてステップ幅を大きくすると，乗り移りや追跡の失敗が起きる危険がある．
- 本実験では，学習と微調整をし直さずに，追跡のパラメータと上限だけを変えて，ステップ数・削減率・追跡の失敗・解の取りこぼし・時間がどう変わるかを調べる．安全な設定の中で最もステップ数の少ないものを開発集合で選び，テストデータで1回だけ確かめる．

## 4．方法（事前登録）

### 4.1．比べる追跡の設定

どの設定でも，予測子は今の実装のまま（1次の微分だけ），最初のステップ幅の上限`max_initial_step_size`は0.05，そのほかの`TrackerOptions`（最小のステップ幅$10^{-12}$，最大のステップ数50000，拡張精度なし）は変えない．表にない`TrackerParameters`は既定値（`a`=0.125，`β_a`=1.0，`β_ω_p`=3.0，`β_τ`=0.4，`strict_β_τ`=0.3，`min_newton_iters`=2）．

| 設定の名前 | 変える値 | `max_step_size` | 意味 | スクリプトでの記号 |
|---|---|---:|---|---|
| 今の設定 | なし | 0.05 | 基準 | A0 |
| 上限なし | なし | 1.0 | 上限だけを外す（EXP-0052と同じ条件を開発集合で） | A1 |
| `β_ω_p`=2.0 | `β_ω_p`=2.0 | 1.0 | | B2.0 |
| `β_ω_p`=1.5 | `β_ω_p`=1.5 | 1.0 | | B1.5 |
| `β_ω_p`=1.0 | `β_ω_p`=1.0 | 1.0 | | B1.0 |
| `β_ω_p`=0.8 | `β_ω_p`=0.8 | 1.0 | 一変数の実験と同じ`β_ω_p` | B0.8 |
| `a`=0.2 | `a`=0.2 | 1.0 | 論文（Timme）の実験の`a` | C |
| 一変数の実験の設定 | `β_ω_p`=0.8，`β_τ`=0.85，`strict_β_τ`=0.8，`min_newton_iters`=1 | 1.0 | 一変数の実験の設定 | U |

- 「今の設定」以外は，すべてステップ幅の上限を外している（1.0）．以下，「`β_ω_p`=0.8」などは，この表の設定（上限なし）を指す．

- ネットワークの出力（中間制御点）は，追跡の設定によらず同じである．スクリプトは，差し替えた設定と元の設定で入力が一致することを目的系ごとに確かめる．

### 4.2．参照の解（取りこぼしの判定に使う）

- 目的系ごとに，線形パスを，HC.jl の慎重な組（`CONSERVATIVE_TRACKER_PARAMETERS`：`β_ω_p`=4.0，`β_τ`=0.25）と`max_step_size`=0.05で追跡し，その終点を参照の解とする．
- 参照の解は，すべてのパスで追跡に成功し，互いに相対誤差$10^{-6}$より離れている（重複がない）ことを確かめる．満たさない目的系は記録し，その目的系は取りこぼしの判定から除く．
- 参照の解と，今の設定の線形パスの終点が一致しない目的系の数も記録する．

### 4.3．第1段：開発集合での評価と選択

- 設定ごと・系の種類ごとに，開発集合の500個で，線形パスと3つのネットワークのパスを追跡する．
- 目的系ごとに記録する値：受理・棄却のステップ数，追跡に失敗したパスの数，取りこぼした解の数（参照の解のうち，どの終点からも相対誤差$10^{-6}$以内にないものの数），追跡にかかった時間（参考値．並列に実行するので，時間の比較には4.5節の計測を使う）．
- **環境の確認：** 今の設定の結果は，既存の開発集合の評価（各runの`evaluation_dev<seed>`）と，線形パスも学習したパスも，受理・棄却のステップ数がすべての目的系で完全に一致すること．

### 4.4．第2段：テストデータでの評価（本実験で1回だけ）

- 今の設定と，第1段で選んだ設定（5節）を，8つの系の種類のテストデータで評価する．記録する値は4.3節と同じ．
- 「上限なし」が選ばれなかった場合，「上限なし」はテストデータでは評価しない（EXP-0052で$d_b=3$の3つの系の種類を評価済み）．
- 選ばれる設定がない場合（5節），第2段は行わない．

### 4.5．時間の計測

- 今の設定と選んだ設定について，`experiments/multivariate_pham/timing.py`で，開発集合の先頭100個の目的系を解く時間を測る（1プロセス・1スレッド，ほかの実験を止めて，5回の中央値．報告の3節と同じ方法）．ネットワークは各系の種類のseed 0だけを使う．
- テストデータでは時間を測らない．

### 4.6．報告する値

- 設定・系の種類ごとに：線形パスと学習したパスの平均ステップ数$\bar J$（学習したパスは3つのネットワークの平均），削減率，棄却ステップの割合，失敗したパスの数，取りこぼした解の数（と，それが起きた目的系の数）．
- 今の設定からの変化：学習したパスの$\bar J$の相対変化と，削減率の変化（ポイント）．どちらも95%区間（目的系ごとに対応をとったブートストラップ，2000回）．
- 時間（4.5節）：目的系1つあたりの追跡時間と全体の時間（ネットワークの計算を含む），今の設定からの変化率．

## 5．判断基準（実行前に固定）

**安全の条件：** ある設定が，8つの系の種類のすべてで，開発集合の線形パスと3つのネットワークのパスのどれにも，追跡に失敗したパスと取りこぼした解が1つもないとき，その設定を「安全」とする．

**第1段の選択（開発集合）：**
1. 今の設定以外のうち，安全なものを候補とする．候補がなければ「選ばれる設定なし」とし，第2段は行わない．
2. 候補ごとに$S=\dfrac18\sum_{\text{系の種類}}\dfrac{\bar J_{\text{学習}}(\text{その設定})}{\bar J_{\text{学習}}(\text{今の設定})}$を求め，$S$が最小の設定を選ぶ．
3. $S$が最小値との差0.01以内の設定が複数あるときは，次の順で慎重な方を選ぶ：`β_ω_p`が大きい方，`a`が小さい方，一変数の実験の設定以外．

**第2段の判定（テストデータ）：** 選んだ設定の，今の設定に対する削減率の変化を，系の種類ごとに次の規則で判定して記録する（EXP-0047以降と同じ）．学習したパスの$\bar J$の相対変化も記録する．

| 判定 | 条件 |
|---|---|
| 良い | 削減率の変化が+1.0ポイント以上で，95%区間が0を含まない |
| 悪い | 削減率の変化が−1.0ポイント以下で，95%区間が0を含まない |
| 差なし | それ以外 |

- テストデータで失敗や取りこぼしが1つでもあれば，それを明記する（選択はやり直さない）．
- 選んだ設定を今後の標準にするかどうかは，結果を報告してユーザーが判断する．標準にする場合，その設定でネットワークを微調整し直すかどうかも別に判断する（本実験の範囲外）．

### 7.5．観察

- **`β_ω_p`を下げると，ステップ数は大きく減った．** 上限を外して`β_ω_p`を3.0から0.8にすると，線形パスも学習したパスも，ステップ数がおよそ4分の1になった（−75〜−77%）．上限を外すだけでは−0.3〜−19%，`a`を0.2にする設定では−14〜−29%だった．
- **この開発集合とテストデータでは，追跡の正しさは保たれた．** すべての設定で，8つの系の種類×500個×（線形パスと3つのネットワーク）の追跡に，失敗も解の取りこぼしもなかった．ただし，`β_ω_p`=0.8は論文が安全係数に求める範囲（$\beta_\omega\ge1$）の外で，今の実装では特異点までの距離による制限も働いていない（報告の5.2節）．ほかの種類の系や，解が近づく目的系で安全とは限らない．
- **棄却ステップが増える．** 今の設定では0%だったが，`β_ω_p`=0.8では線形パスで11〜31%，学習したパスで3〜26%になった．ステップ数はそれでも大きく減っている．
- **削減率（線形パスに対する学習したパスの利点）は，少し下がる系の種類が多い．** テストデータで，n2-d33は+1.6ポイント（良い），n3-d333とn4-d3333とn5-d33333は差なし，残りの4つは−2.7〜−3.7ポイント（悪い）だった．ネットワークは今の設定の追跡で微調整したものなので，`β_ω_p`=0.8の追跡で微調整し直せば変わる可能性がある（本実験では調べていない）．
- **時間：** ステップ数の減少に応じて，追跡の時間も短くなった（n5-d33333の学習したパスで46.3 msから12.1 ms）．その結果，ネットワークの計算（1.2〜1.8 ms）の割合が大きくなり，`β_ω_p`=0.8の線形パスより速かったのはn5-d33333の学習したパスだけだった．今の報告の比べ方（今の設定の線形パスとの比較）では，n3-d333以上で速くなった．
- 判断（ユーザーに提案すること）：`β_ω_p`=0.8・上限なしの設定（または，棄却は多いがステップ数がさらに少ない一変数の実験の設定）を今後の追跡の標準にするか，その設定で微調整し直すかを決める必要がある．

### 7.6．訂正（2026-10-17，実験の後に判明）

- `eval_arm.py`は，参照の解を求める環境（慎重な設定）と評価する環境（比べる設定）を，同じプロセスの中で作っていた．同じプロセスの中で作った環境は，Julia側の追跡の状態（ホモトピーと追跡の設定）を1つ共有しており，最後に作った環境の追跡の設定が，すべての環境の追跡に使われる．このことは，EXP-0055の準備中（2026-10-17）に，同じスクリプトの構成で設定ごとの結果が一致してしまうことから気づき，確かめた．
- そのため，参照の解は，4.2節に書いた「慎重な設定（`CONSERVATIVE`，上限0.05）で追跡した線形パスの終点」ではなく，**比べる設定と同じ設定で追跡した線形パスの終点**だった．
  - 線形パスの「取りこぼした解」は，自分自身と比べているので常に0になり，意味を持たない．7.2節の「今の設定の線形パスの終点は，すべての目的系で参照の解と一致した」も同じ理由で意味を持たないので，取り消す．
  - ただし，参照の解の確認（すべてのパスで追跡に成功し，終点に重複がないこと）は，すべての設定・系の種類・目的系で満たされていた（開発集合とテストデータ）．Pham系の解はちょうど$N$個（$N$はパスの数）なので，**比べたどの設定でも，線形パスはすべての解に着いていた**．学習したパスの取りこぼしが0であることは，学習したパスもすべての解に着いたことを意味する．
  - したがって，安全の条件（失敗も取りこぼしもないこと）の判定と，選んだ設定の結論は変わらない．変わるのは，取りこぼしを判定した基準（参照の解）の作り方だけである．
- ステップ数，削減率，時間には影響しない（評価する環境は，最後に作られたので正しい設定で追跡していた）．
- EXP-0055からは，使う環境の追跡の状態を，追跡の前に毎回初期化し直す（`outputs/EXP-0055/scripts/label_paths.py`）．
